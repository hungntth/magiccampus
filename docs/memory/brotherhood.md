# Sworn brotherhood / Kết bái (M14 phase C)

Plan: `docs/plans/2026-11-04_17_SOCIAL_PVP.md` §2.3 / §3.6 / §7 C. Legacy: `E:\mcgame\docs\memory\sworn-brotherhood.md`, Go `application/brotherhood/*`, `handlers/brotherhood/*`. Implemented 2026-11-12. Brother relationship rows (type 6) come from `RelationshipService` (`social.md`).

## Contract (`packages/shared/src/brotherhood.ts`)
- `BROTHER` tuning: title 153, Lv >= 25, fee 2 000 000 silver per newcomer, title 300 gold, leave 100 gold, leave penalty 2500, 2-5 members, 60 s answer window, title 1-8 characters. `NPC_BROTHER` (npc 1637, `brother_` prefix) and `BROTHER_FUNC` (`brother_swear|title|leave|disband|guide`). `BrotherKind` SWEAR 1 / JOIN 2 / DISBAND 3.
- Payloads: `AgreeSetBrother {cname}`, `BrotherTitleUpdate {cid, tname, enable}`, `AcceptNewBroMemArgs` (`names[], hasBrother` positional), login extra `BrotherLogin {broT}` (on `PlayerData`), `SceneCharacter.broT?`.
- Texts: `BROTHER_TEXT` (Flash CALLBACK_S[196-207] prompts) and `BROTHER_SAY` (server lines). Pure: `normalizeBrotherTitle`, `brotherFee`, `leaveIntimacy`.

## Server `modules/brotherhood/`
- `brotherhood.schema.ts` + `brotherhood.store.ts` + `brotherhood-core.module.ts`: collections `brotherhoods {_id (counter 'brotherhoods'), title}` and `brotherhood_members {characterId unique, brotherhoodId, joinedAt}`. The core module (models + `BrotherhoodStore` only) is imported by `SceneModule`, which cannot import the feature module (Scene -> Brotherhood -> Social -> Combat -> Scene). `store.decorate(sc)` adds `broT` to scene payloads (30 s title cache, forgotten on every write), `titleOf` feeds the login extra.
- `brother-rules.ts` (pure): `checkTeamOnMap`, `planSwear` (size 2-5, Lv >= 25, one group, join needs every brother present, friend / brother row per newcomer pair, enemy / black / tutor / couple refused, fee vs. moneyBind + money), `planDisband`, `silverSplit` (moneyBind first), `planLeave`. `brother-ceremony.ts`: in-memory drafts + live ceremonies (clock injected, one NO cancels, runs once).
- `brother-team.service.ts` (read-only team facts + plan), `brotherhood.service.ts` (start swear / disband, `begin`, `answer`, `forget`), `brother-exec.service.ts` (final steps, leave, title), `brother-push.service.ts` (say / wallet / `onBrotherTitleUpdate` / title 153 grant + revoke / IM refresh), `brother-npc.service.ts` (NPC 1637 menu hooks), `brotherhood.rpc.ts`, `brotherhood.module.ts` (login extra + disconnect / character-leave cleanup).
- RPCs (none quiet, all `forbidInBattle`, replies `null`): `beginBrother`, `becomeBrother(bool)`, `acceptNewMemToBrother(bool)`, `disbandBrothers(bool)`, `breakBrotherShip`, `updateBrotherTitle(title)`. Refusals are `RpcException.forbidden` toasts with the Go texts; answers to an expired ceremony are an `onSystemSay` line.
- NPC 1637 (a normal static NPC on map 10): click -> `onList` ("Nhiệm vụ" when it has quests -> `open_npc_interaction_1637`, "Kết bái", member-only "Đặt danh hiệu kết bái (300 vàng)" / "Rời nhóm kết bái" / "Giải tán nhóm kết bái", "Hướng dẫn kết bái"). `brother_swear` -> `onSystemSay(fee)` + `onLeaderConfirmToBro`; `brother_title` -> `onUpdateBrotherTitle`; `brother_leave` -> `onBreakBrother`; `brother_disband` -> `onBeginDisbondBrothers` to every member; `brother_guide` -> guide lines through `onSystemSay` (an NPC bubble cut the text). The funcs do not check NPC distance (Go parity), only the team rules, so the IM tab can call `npcScript('brother_disband')`.
- Flow: draft (60 s, leader) -> `beginBrother` re-plans the same team, registers the ceremony (leader agreed) and sends `onAgreeSetBrother {cname}` (new group) or `onAcceptNewBroMem(names, hasBrother)` (join) -> answers. One NO -> `onFailToBecomeBrother(cid)` / `onFailToAcceptNewBroMem(cid)` / `onFailToDiabondBrothers(cid)` to participants on the refuser's map, an `onSystemSay` line to the others. Last YES -> `BrotherExec`:
  - Locks `brother:<id>` for every participant (ascending), re-plans from fresh data (party, presence, levels, rows, silver), then spends moneyBind then money (conditional, refunded on any later failure), writes the group (unique member index), `RelationshipService.link(.., BROTHER)` for every pair involving a newcomer (friend intimacy kept; rolled back to friend rows on failure).
  - Pushes: `onAddMoney` + `onUPP` per silver kind, `onInitViewImC` to all, success line, world `onSystemSay`, leader `onSetBrotherTitle` (new group) or the joined line + title 153 for newcomers when the group already has a title.
- `updateBrotherTitle`: 300 `gold` (unbound, conditional), `BrotherhoodStore.setTitle`, title 153 `TitleService.grant` for every member + `onBrotherTitleUpdate {cid, tname, enable:false}` broadcast to each member's map, line to all. The title is not force-activated.
- `breakBrotherShip`: 100 gold, leaver's rows (both directions, with each other member) -> friend rows via `convert`, -2500 intimacy floor 0 (`addIntimacy`, `onSetClose` for changed rows), member row removed, a group left with < 2 dissolves, title 153 revoked for the leaver (everybody when dissolved), suffix cleared, IM refreshed, lines to the others.
- Disband: every member of the leader's group must be in the leader's team on his map; unanimous (leader included); rows back to friend rows (no penalty), title revoked for all.
- `TitleService.revoke(characterId, titleId)` (new): deletes the owned row, clears an active title (buff off, stat refresh, map `onTitleUpdate` tid 0), pushes `onAddTitle {f: 5, t, ct}` (list refresh, no toast). Not callable inside the character's own lock.
- Disconnect / character leave: draft and live ceremony dropped, the other participants get a "đã rời đi" line.
