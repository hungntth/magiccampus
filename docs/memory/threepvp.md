# Chiến Trường Dũng Sĩ (3v3 room PvP, M14 phase H)

Plan: `docs/plans/2026-11-04_17_SOCIAL_PVP.md` §2.7 / §3.10 / §11 (phase H). Legacy: `E:\mcgame\docs\memory\threepvp.md`. Implemented 2026-11-12. Shared `threePvp.ts` (constants, wire types) + `threePvpRules.ts` (pure rules, 12 tests).

Level 50+ players open activity icon 22 during **Friday 19:00-22:00 UTC+7** (or a GM test window), are teleported to map 73 (2600, 760), form rooms of 1-3 (partial rooms may match), ready up, the leader starts, and the server pairs queued rooms every 5 s into a 3v3 system PvP (characters + battle pets). Points by the room size at the start: win 3 / 6 / 10, loss or draw 1 / 2 / 3. At the end ranked players get medals (currency 225 `threePvpPnt`) = points x 10 + rank bonus (1: 500, 2-3: 300, 4-10: 200, 11-50: 100), spendable in shop 85 slot 4354 (price type 7) and used for titles 220-229 at NPC 1860.

## Server (`modules/threepvp/`)
- `threepvp-state.ts` (`ThreePvpState`, in `ThreePvpCoreModule` so `ActivityService` can add the strip entry of icon 22): run window, room registry, last rank, `stripEntry` / `statePush` (`updateActivityState {id 22, flag 2 fighting | 0}`; also at login through `SceneHooks.onMapChanged`).
- `threepvp-rooms.ts` pure `RoomBook` (smallest free id, join refusals in the Go order full / queued / level / password, seat renumbering + ready reset on removal, `normalizePass` digits <= 6 without leading zeros, `clampLimit` [50, 160]); `threepvp-rooms.service.ts` flows + pushes; `threepvp-match.service.ts` pairing + battle end hook; `threepvp-run.service.ts` 1 s tick (open, announce 18:30 / 18:55, end of fighting, settle once no arena battle is left or +5 min, empty map 73 60 s later); `threepvp-progress.service.ts` points / ranking / payouts; `threepvp-streak.service.ts`; `threepvp-npc.ts`; `threepvp.rpc.ts`; `event-progress.schema.ts`.
- RPCs (none quiet, replies as in Go): `checkPVPLine` -> boolean, `initPVPRoom` -> roomMap (teleport **before** the reply; leaves a party first), `getLastPVPRank` -> `[{name, rank, pnt}]` (top 20), `createPVPRoom` / `addPVPGroup(roomId, leaderId(ignored), pass)` / `quickEnterRoom(roomId, pass)` -> room or null, `leavePVPRoom` (teleports back to the remembered origin, fallback map 38 2090,890; ignored in battle), `leftPVPGroup` (stays on the map; `{}` outside a room, null while queued / fighting), `PVPKickByLeader(cid)`, `updatePVPGroupLimit(min, max)`, `updatePVPGroupPass(pass)`, `readyOrStartPVP`, `quickInvite`, `sureInvite(inviterCid, roomId, 1|-1)`. Refusals are `onMidNote` + a null reply. GM: `gmThreePvp(minutes)` (`requireGm`, default 15, min 5, max 180) and the H5 dev helper `gmThreePvpStop` (ends the window; settles when the arena battles are over).
- Pushes: `onCreatePVPRoom`, `onAddRoomMember`, `onEnterPVPRoom`, `onPVPKickByLeader(roomMap)`, `onUpdatePVPRoom {type 'level' | 'pass'}`, `onPushPVPQueue {type 1 (ready, index = seat 2|3) | type 2 (state 2 queued, 0 off)}`, `inviteByLeader {cid, index: roomId, name}`, `onRefreshPVPPoint`, `onUpdateMyPoint {rank, point}`, `showPVPGroupResultAlert {rank, point, pvpPoint}` (both = medals), `updateActivityState {id 22}`, world `onRedMsg` notice "[Chiến Trường Dũng Sĩ] A, B đã đánh bại C!" / "... bất phân thắng bại!".
- **armLeader**: for every empty seat the leader gets `onPushPVPQueue {type 1, index: seat, cid: 0, state: 1}` + `onAddRoomMember` (after create / join / removal / re-entry, never while queued) so the Flash leader gate lets a partial room start. The H5 client ignores `cid 0`.
- **Password**: the wire room carries `pass` masked (`'*'` locked, `''` open); only the leader's own `onUpdatePVPRoom {type 'pass'}` has the digits. An invited character (quickInvite) joins without it.
- Matching pool: queued, not fighting, rest over (20 s after a win, 15 s otherwise), every member online, on map 73 and not in a battle. `pairRooms`: size desc, strength (sum of levels) desc, id asc, avoids the last opponent unless nobody else is free. The arena **always starts at full HP / MP** (deviation: Go used the current HP) and ends that way (`BattleContext.restoreAll`).
- Result (`decideResult`): a wiped side loses, both wiped = draw, else the combat result, round cap = draw; a fled or disconnected member drops out like a group battle (the side loses once nobody is alive). Only members that fought, did not drop and still stand on map 73 score. Loss streak per room: 5 losses in a row -> buff 2435 for every member (3 h), each further loss upgrades to 2439; a win, a leave, a kick or the settlement removes it; a draw keeps it.
- Persistence `event_progress {characterId, event, periodKey, total, claimedTiers}` (unique triple): `threepvp` (period = run key, points, tier 1 = medals paid), `threepvp_medal` ("all", lifetime medals), `threepvp_title` (YYYY-MM, tier 1 = claimed). Payout = guarded claim (`claimedTiers $ne 1` -> `$addToSet`) then the credit; a failed credit `$pull`s the claim back (Go burnt it). Online ranked players are paid at settlement and see the popup; others claim at NPC 1860 ("Nhận phần thưởng còn lại", only while no run is open). Title: NPC 1860 "Nhận danh hiệu Dũng Sĩ", highest of 220-229 by lifetime medals (1200 ... 50000), 30 days, once per UTC+7 month (claim first, grant after, rolled back on failure).
- Combat changes: `PvpService.startSystem(sideA, sideB, ctx)` (up to 5 per side; attackers 10..14 + pets 15..19, targets 0 2 1 4 3 + pets +5), `systemBoard` / `aliveCharacters` / `restoreFull` in `pvp-rules.ts`, `BattleContext.restoreAll` / `alive`, `settlePvp` now runs the end hooks, tagged system battles use the group-battle disconnect path (a duel still loses on leave). Manual `PVPStartClient` on map 73 is refused ("Không thể khiêu chiến tại Chiến Trường Dũng Sĩ, ...").
- Shop 85: price type 7 (`p_type2 = 7`, slot 4354, 20 medals) is a `PointPrice` -> `CurrencyService.spend` (items unbound, a Go-assumption), the slot view shows the special price. The shop NPC is 1520 on map 9 (Giác Đấu), not NPC 1860.
