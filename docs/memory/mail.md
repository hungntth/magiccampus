# Mail (Thùng Thư) and system mail (M11 phase A)

Plan: `docs/plans/2026-11-04_14_MAIL_AUCTION_BAGS.md` (phase A). Legacy: `E:\mcgame\docs\memory\mail-system.md`, Go `internal/application/mail`, `internal/domain/mail`, `handlers/mail`. Implemented 2026-11-05.

## Contract (shared `mail.ts`)
- RPCs (none quiet): `showMailP()` -> `{mailList, currentTime}`; `addMail(name, obj, pw)` (proxy, no reply; pw ignored); `takeMail(id[, confirm])` -> id | 0 (a truthy 2nd argument confirms a COD mail); `setReadDate(id)` -> `{id, newDate}`; `delMail(id)` -> id | 0; `delMails(ids)` -> ids; `closeMail` no-op; GM `devSendMail(name, templateId, count[, money, gold])` (`requireGm`).
- Pushes: `initViewMailMngP()` (NPC type 3 click or `npcFuncClick`), `onAddMail(MailView | {id:-1, type})` (receiver gets the mail, the sender gets an echo with `receiverName`), `onDelMail(id)` (sweeper), `onDelCharactorSlot` / `onDelPet` / `onUPP` to the sender, `onAddItem` / `onAddCharactorSlot` / `onAddPet` / `onUPP` on take. Login: `PlayerData.mailUnread`, and 6 s later up to 5 unread mails as `onAddMail` (oldest first).
- `MailView`: Go keys (`senderId` "0" for system, `sn`, `codFlag`, `itemType` 29 | 19 | 12, `itemId` template id, `readDate` -1 unread) + H5 `returned`, `attachment` (name, iconCode, color, count, `item: BagItem` / `pet: PetWrapper` for tooltips). Player text is HTML-escaped by the server, system text is raw HTML.
- Refusal texts are the Go strings (`MAIL_TEXT`). No postage; gift money / gold is moved (unbound Bạc / Vàng only). Level gate `PLAYER_EXCHANGE_MIN_LEVEL = 0` (stock Flash; legacy Open Beta 60).

## Server (`server/src/modules/mail/`)
- `mail.schema.ts` (`mails`, counter `mails`; `claimed`, `returned`, `readAt`, unique sparse `source`), `mail-rules.ts` (pure, +test), `mail-saga.ts` (`UndoStack`, +test), `mail-core.service.ts` (insert / views / pushes), `mail-send.service.ts`, `mail-take.service.ts`, `mail-delete.service.ts` (delete + expiry + return mail), `mail-sweep.service.ts` (5 s after boot, then hourly), `mail.service.ts` (list, read stamp, unread, login extras, escrow owner), `mail-system.service.ts` (PUBLIC API), `mail.rpc.ts`, `mail.module.ts` (exports `MailSystemService`, `MailService`).
- Escrow (`inventory/escrow.service.ts`): an attached item row moves to `characterId 0 / slotType 90 / slotIndex = itemId / escrowRef 'mail:<id>'` with ONE conditional updateOne (the whole stack, id and rolls preserved); a pet gets `characterId 0 / escrowRef`. Delivery = one conditional move into the receiver's free slot (a matching stack with room takes the whole count instead: delete-then-increment, the row is re-created if the guard misses). The startup self-check logs `escrow self-check: N open ref(s), no orphans`; each feature registers `registerOwner(prefix, liveIds)`.
- `withKeyLock(key, fn)` and `withCharLocks(a, b, fn)` (ascending ids) in `inventory/char-lock.ts`; the mailbox cap is re-checked under `withKeyLock('mailbox:<receiver>')`.
- `pet/pet-transfer.ts`: unbound, resting, not following, no gear (shared by mail, phase B auction and phase D trade).
- `TradeBook.isLocked(cid)` (`TradeManager` exported from `TradeModule`): `addMail` is refused while the sender has a locked offer; `takeMail` of an attachment too.

## Sagas
- **send** (sender char lock): trade lock -> level gate -> receiver by name -> self -> balance -> box cap -> escrow attachment -> debit gift (`spendMoney`) -> insert under the mailbox lock; every failure undoes the earlier steps in reverse (refund, restore the row to its slot).
- **take** (receiver char lock): owner + content + COD confirmed + COD funds -> claim (`claimed: false -> true`) -> spend COD -> deliver attachment (template: `InventoryService.canFit/add`, bound / colour from the mail; escrow: release) -> credit gift -> COD payment system mail to the sender (`source mail:<id>:cod`, title `Thu phí thư`). A full bag / pet bag undoes the claim and the COD.
- **delete / expiry** (30 days unread, 10 days after read): a player mail with content left returns to its sender as `Thư bị trả lại` (`returned = true`, COD dropped, escrow retagged to the return mail, `source mail:<id>:return`); system attachments are destroyed (decision Q6: this includes unclaimed auction wins). Listing (`showMailP`) purges the owner's expired mail first.

## System mail API (for every other feature)
`MailSystemService.sendSystemMail({ receiverId, title, text, senderName?, money?, gold?, item?: { templateId, table: 29 | 19, count, bound, quality? }, escrow?: { fromRef, itemId } | { fromRef, petId }, source? }) -> MailView | null`. Ignores the box cap, pushes `onAddMail` to an online receiver. `source` = idempotency key (unique): a retry never inserts twice (it re-runs the escrow retag and returns the existing mail). `escrow` parks existing goods: pass the ref they are under now (`'auction:17'`), the service retags them to `mail:<newId>`. `broadcast(range, mail, sourcePrefix?)` for events. `null` = unusable input, unknown receiver or missing escrowed goods (logged).

## Rewards moved to mail (Go delivered these by system mail)
- **Quiz** (`modules/quiz`): the Túi Quà Đố Vui bags (item 4875, bound, count = tier + rank bags) are ALWAYS mailed (sender `Đố Vui Có Thưởng`, title `Phần thưởng Đố Vui Có Thưởng`, Go text with points and rank, `source quiz:<cid>:<settle second>`). Exp stays direct for online players; an offline player keeps `owedExp` (Go has no such case) paid at the next login. Legacy `owedBags` rows are converted to a mail at the next login (`claimOwed`, take-then-mail). `unpack` of 4875 was empty (no `data_tbl_item_award` rows), so the bag item is what H5 can hand out; H5 cannot open gift bags yet.
- **World boss** (`modules/worldboss`): unclaimed bags (offline, full bag at settlement, left the map, evacuation, fresh event) are mailed one mail per bag item (bound) as Go `exit.go mailPendingAward`: sender `Boss Thế Giới`, title `Phần thưởng BOSS Thế Giới`, text with class / world rank (`-` when unknown), `source wb:<runSeq>:<cid>:<i>:<item>`; chat line `Phần thưởng BOSS Thế Giới đã được gửi vào hộp thư của bạn.`. A failed mail falls back to `character_wb_owed`, which login converts to mail again (legacy M10 rows too). The in-event claim (`takeWbAward`, bag unpack) is unchanged.
- **Left alone (Go did not mail)**: dungeon / tower / star / chest / diary / sign-in / feast / VIP / forge / guild bank / shop refusals on a full bag, battle loot overflow (Go uses the temp bag: phase C), trade. Medals, dust, explorer points: no H5 system, still logged-and-skipped.
- **Go mail senders with no H5 feature yet**: Giác Đấu, Thi Câu Cá, Vô Ưu Viễn Chinh, Open Beta daily gift, Ảo Cảnh Tầm Bảo, Sổ Tay Ma Thú orange accessory when the bag is full, over-level gear released at character select. Wire them through `sendSystemMail` when those features arrive (texts are in the research notes of this phase's session: see Go `dogfight/settle.go`, `fishcontest/rewards.go`, `crosscontention/settle.go`, `openbeta/service.go`, `aocanh_hooks.go`, `boss_daily_bonus_extras.go`, `over_level_gear.go`).
