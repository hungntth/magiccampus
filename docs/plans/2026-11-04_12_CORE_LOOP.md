## 2. Confirmed mechanics

### 2.1 Hotbar (9.2)
- **Slots and storage:** 30 slots `s1..s30`, 3 bars of 10 (`UserBarCanvas.as:96`). Each slot is two `interfaceData` keys: `st<n>` (52 = skill table, 29 = item template) and `sid<n>` (skill id or item template id). Login defaults are `st1..30 = 0` and `sid1..30 = 0` (`interface_settings.go:391-420`).
- **`skillSetUserBar(skillId, level, "<n>")`** (`interface_settings.go:113-157`):
  - The slot arrives as a numeric string and must be 1..30, else invalid args. `level` is only checked for being an integer.
  - Ownership: an exact id, or the same `code_name` family learned at a level ≥ the requested one (`service.go:117-132`), or an owned pet's skill.
  - Writes `st<n>=52`, `sid<n>=skillId`, replies `true`, sends no push. The client sends it with no Responder.
- **Items** go through `uif("st<n>", 29, false)` + `uif("sid<n>", templateId, false)`.
  - Clearing a slot is `uif("sid<old>", 0)` (drag off, or move to another slot).
  - Client accept rule (legacy patch): refuse only when the template has no `skillId` and `useType >= 4`.
- **Bar visibility:** `uif("au", 0|1)` (`changeBarVisible` l.2026); `initView` restores it.
- **Lock:** `us({ubl})` saves it, but the bar always starts unlocked (`AutoBattleCanva.as:183-262`). Tooltip `Nút khóa phím tắt`.
- **Page switch:** Up cycles 1→3→2→1, Down cycles 1→2→3→1. The page is not persisted. H5 `userBar.ts` already does this.
- **Keys 1-0** (`useSlotByNum` l.1489-1510):
  - In battle with the command menu up: slot `n + page*10 - 10`, or slot `n` of bar 1 when `battleStExpan` is set.
  - Out of battle: only item slots fire.
- **Mouse:**
  - Single click uses a slot in battle, and on the map only while the bar is locked.
  - Double click always uses it.
  - Ctrl+click on an item targets the active pet (`Player.as:792-818`).
- **`useSlot`** (l.1014-1088):
  - Item: first bag stack of that template, else `Không có vật phẩm này` and alpha 0.5. On the map → `useItem(1|2, petId, slotId)`. In battle → the item command (-60) with target selection.
  - Skill: only in battle while commands are open. HP/MP check via `checkSkillRequire`.
    - Self-target skills (player / pet) send at once.
    - Others open target selection.
    - A pet-self skill with no pet shows `Pet chưa lâm trận không thể dùng kỹ năng này`.
  - **A skill slot does nothing on the map.** No RPC exists for that.
- **Display:** item slots show the bag count (alpha 0.5 at 0). Skills are dimmed when HP/MP is short; in the pet turn only pet-usable skills are enabled. There is no cooldown display.
- **Strings:**
  - Toggle tooltip: `Mở/Ẩn thanh kỹ năng \rKhi chiến đấu nhấp đơn để dùng\r Khi không chiến đấu nhấp đôi để dùng` (`USERBARCANVAS_S[0]`).
  - Empty slot: `Khi chiến đấu nhấn chuột để sử dụng nhanh\r Trên bản đồ nhấn đôi chuột để sử dụng nhanh` (`[2]`).
  - Pet missing: `[1]` above.

### 2.2 Skill window, learning, training (9.3)
- **Window "Kỹ năng"** (`SkillManager.as`): the tab index equals `use_env`.

  | Tab | Label | Port |
  |---|---|---|
  | 0 | `Chủ động` | yes |
  | 1 | `Bị động` | yes |
  | 2 | `Hôn nhân` | deferred |
  | 3 | `Luyện` | yes |
  | 4 | `Bang hội` | deferred |
  | 5 | `T\nkhí` | deferred |
  | 6 | `KN\nsống` | deferred |

  - The header shows the `expSkill` currency field.
  - Listed rows (`SkillManager.as:1160-1300`):
    - learned skills by `use_env`;
    - unlearned level-1 class rows (`req_class` contains `|classId|`) with `req_level <= level` for `use_env` 0/1/3;
    - all level-1 `use_env 3` rows ordered by `TRAINING_SKILL_ORDER`.
  - `req_c_l == 10` rows are hidden without rebirth (H5 has none, so always hidden).
- **Buttons** (`SkillUseSlot.as:399-491`): `Học` / `Nâng` / `Đầy cấp` (`SKILLUSESLOT_U[2]/[1]/[0]`), with confirms `Bạn xác nhận học: {skillName}?` / `Bạn xác nhận thăng cấp: {skillName}?`.

  | use_env | Học | Nâng |
  |---|---|---|
  | 0 / 1 | `useItem(1, -1, bookSlotId)` (the skill book) | `skillLearnByClient(nextLevelId, position)` → Boolean reply |
  | 3 | `addTrainingSkill(level1Id)` (null Responder) | `skillLearnByClient(nextLevelId)` |

  - Enable rule `enableBtnReqSkill` (l.566-624): `level >= reqLevel && expSkill >= exp_skill && (money >= price || moneyBind >= price) && cl >= req_c_l`. An unlearned 0/1 row also needs the book in the bag.
- **`skillLearnByClient`** (`combat/battle.go:601-688` → `UpgradeNormalSkill` `normal_upgrade.go:30-97`):
  - Validation (`service.go:300-344`), in order: template exists → `req_level` → `req_class` → class rank (`req_c_l <= 0` passes; `10` needs rebirth; else `cl >= req_c_l`).
  - Family by `code_name`: none learned → `Chưa học kỹ năng này`; requested level ≤ current → `Kỹ năng đã đạt cấp này`; not exactly current+1 → `Phải thăng từng cấp một`.
  - Cost (`chargeSkillCost`): `exp_skill > pool` → `Kinh nghiệm không đủ.`. Price is paid **whole** from `moneyBind` if it is ≥ price, else from `money`, else `Bạc không đủ` (never split). Then the pool drops by `exp_skill`.
  - The learned row is moved in place (`skillId` = next id, `level`).
  - Failure: `onSystemSay(msg)`, reply `false`.
  - Success pushes, in order:
    1. `onUPP {expSkill, exp, money, moneyBind}`
    2. `onSkillUpdate(list)`
    3. `onMWeaponSkillUpdate(list, true)`
    4. a stat-refresh `onUPP` when the skill is passive (type 11).
    - Then reply `true`.
- **`addTrainingSkill(id)`** (`training_skill.go:23-32` → `LearnPaidSkill` `family.go:49-87`):
  - Needs `use_env == 3`, else `Không phải kỹ năng tu luyện`.
  - Same validation; uses the family's level-1 row; refused if any level of the family is owned (`Kỹ năng đã đạt cấp này`).
  - Same cost; creates the row.
  - Same pushes. On failure `onSystemSay` plus the skill lists.
  - Data example SKILL493201 "Luyện Sinh Mệnh Sơ Cấp" (`req_c_l 1`):

    | Level | id | req_level | exp_skill | price |
    |---|---|---|---|---|
    | 1 | 3857 | 45 | 400000 | 14000 |
    | 2 | 3873 | 60 | 500000 | 18000 |
    | 3 | 3874 | 75 | 700000 | 23000 |
    | 4 | 3875 | 90 | 1500000 | 53000 |
    | 5 | 3876 | 105 | 2000000 | 68000 |

- **Skill books** (`effect_skill_book.go`, item type 505 "Sách Kỹ Năng - <skill>"):
  - The book name suffix (after `sách kỹ năng`, then after `-`, trimmed and space-collapsed, case-insensitive) is matched against level-1 skill names with `use_env != 5`. A row of the player's class wins; otherwise the first match.
  - Then normal validation (level/class/rank). **No exp or silver is charged.** Refused if the family is already learned.
  - The book is consumed only on success; message `Đã học kỹ năng từ <book>.`, else the error text or `Không thể học kỹ năng`.
- **Error strings** (`SkillErrorMessage`, verbatim): `Chưa học kỹ năng này`, `Kỹ năng đã đạt cấp này`, `Phải thăng từng cấp một`, `Kinh nghiệm không đủ.`, `Không phải kỹ năng tu luyện`, `Không tìm thấy kỹ năng của sách này`, `Cấp độ nhân vật không đủ`, `Bạc không đủ`, `Cấp chức nghiệp không đủ`, `Cần chuyển sinh để học kỹ năng này`, `Nghề nghiệp không phù hợp`.
- **Tooltip** (`TIPREQSKILL_S`): `Sách kỹ năng cần: {skillBook}`, `Cấp độ nhân vật cần: {playLevel}`, `Kinh nghiệm thăng cấp cần: {levelExp}`, `Tiền thăng cấp cần: {levelMoney}`, `Cấp độ nghề cần: {proGrade}` (`CLASS_LEVEL[req_c_l]`), `Đã max cấp`.
- **expSkill pool = the legacy `Character.Experience`:** the in-level exp counter (`character.go:563-616`).
  - Every exp gain adds to it.
  - Below level 20 it auto-levels by subtracting the next level's need.
  - From 20, `lvUp` (`ManualLevelUp`) spends it.
  - So skill learning and levelling compete for the same exp. Login sends `expSkill` (`login_payload.go:204`); exp pushes add `expSkill` only when gain > 0 (`exp_helper.go:46-48`).
- **Training stat bonus** (`training_bonus.go`, owner-tuned):
  - Formula: `base × level × tier × 10`, with base HP 110 / phys def 30 / magic def 30 / speed 3 and tier Sơ 1 / Trung 2 / Cao 3.
  - Applies only to rows with kind 5, type 11 and a name starting with `Luyện `.
  - Character only, added flat into base stats. At Lv10 all twelve chains give +66 000 HP, +18 000 def, +18 000 mdef, +1 800 speed.
- **Class rank `cl` 0..5** (`class-rank-promotion.md`, Go `quest/class_rank.go`):
  - Ranks: Kiến Tập → Sơ Cấp → Trung Cấp → Cao Cấp → Chuyên Gia → Tông Sư.
  - Finishing the final quest of a chain sets the rank (never lowers it): 686-691 → 1, 677 → 2, 2471 → 3, 4045 → 4, 5414 → 5. Push `onUPP {cl}`; Flash prints `Bạn đã phổ cập thành: {prefix}{className}` (`CALLBACK_S[25]`).
  - The 3-1 turn-ins need the previous rank: 143/287/639/640/643/644 need cl ≥ 1, 2464-2469 ≥ 2, 4038-4043 ≥ 3, 5407-5412 ≥ 4. Refusal info: `Cấp độ nghề chưa đủ để hoàn thành nhiệm vụ!`.
- **Skill damage numbers** (`application/combat/skill_adapter.go:6-8`, `skill_damage_desc.go`):
  - `exp_skill` / `dex_skill` are **upgrade costs, not damage values**.
  - Damage skills (types 1-4) take a ratio from the description (`Gây 110% sát thương ma pháp` → attack × 1.10, base 0; the earliest ratio wins, skipping ratios after `chuyển|lấy|giảm|tăng|hấp thu|phản|gấp`).
  - Everything else: flat 10 plus multiplier `1 + min(req_level, 200)/200`.

## 3. Decisions for H5

1. **Phase order.** The auto-battle plan is Phase A as written. It creates `modules/settings/` (`uif`, `skillSetBattle`) and `Character.interfaceData`, which the hotbar and the settings panel reuse. Each later phase extends that module instead of adding another.
2. **expSkill pool:** no new counter. H5 `exp` is cumulative (`LEVEL_EXP`), so the legacy in-level pool is derived: `expSkill = exp − LEVEL_EXP[level − 1]`. Spending lowers `exp` but never below `LEVEL_EXP[level − 1]`, so the level is unchanged and the manual `lvUp` threshold competes with learning exactly as in legacy.
   - This revises the coordinator default "add an `expSkill` field": the legacy evidence says the pool is the experience itself.
   - Login `PlayerData.expSkill` and every exp `onUPP` carry it.
3. **Class rank `cl`** is added to `Character` (default 0) in Phase B with the promotion rules of §2.2. The rules are small: a final-quest table plus a turn-in gate.
   - An idempotent `server/tools/backfill-class-rank.ts` sets `cl` from each character's `questLog`.
   - The Tông Sư "học đủ tất cả kỹ năng tu luyện" condition is not enforced (same as Go). Rebirth (`req_c_l 10`) rows stay hidden and refused.
4. **Skill damage base stays on `exp_skill` (user decision 2026-11-04):** `skill-data.ts` keeps reading the damage base
   from `exp_skill` (and `dex_skill` as the multiplier), as M2 does today. The Go description-ratio rule (§2.2) is **not**
   ported. `exp_skill` is also the learning/upgrade cost (§2.2), both uses read the same column.
   - Upgraded rows have `exp_skill` up to 5·10⁹, so once Phase B allows upgrades the implementer must browser-check a few
     upgraded class skills and report the damage numbers to the user before quieting the feature (risk 1). No clamp or
     rebalance is added unless the user asks.
5. **Skill window tabs:** `Chủ động`, `Bị động`, `Luyện` only. Hôn nhân, Bang hội (the guild skill panel already exists in M6 and stays where it is), T khí (M7 magic weapon has its own window) and KN sống are hidden.
   - Awakened `exSid` variants are shown and accepted only if `docs/memory/stat-features.md` already exposes the awaken points; otherwise they are deferred (open question 4).
6. **Training stat bonus** goes through the stat-provider registry (`stats/stat-provider.ts`) as a `training-skill` provider, character only, with the owner-tuned constant 10.
7. **Hotbar storage** is `Character.interfaceData` (`st<n>`, `sid<n>`, `au`, `ubl`). `skillSetUserBar` uses H5 `SkillService.owns` extended to family ownership. The pet-skill branch is accepted only for the active pet's skills. Item keys go through `uif` with a whitelist (`st<n>` ∈ {0, 29, 52}, `sid<n>` integer ≥ 0, n 1..30).
8. **Relive modes:** H5 currently answers 2 everywhere. Phase D answers 1/2/3 per §2.3. The world-boss map id is a constant `WORLD_BOSS_MAP_ID` (conflict: Go code 2006 vs memory doc 47, see open question 3); H5 has no world boss, so mode 3 is reachable only in tests.
   - `bbGoldRelive` checks the price **server-side**: the server stores the death time and charges `int(remaining/5)+1` (clamped 1..6), ignoring the client value. This fixes the Go bug.
9. **Death penalty** (20 % durability on `toSafe` in mode 1, level ≥ 20) is ported: the forge/repair code already models durability.
   - Fashion items are skipped.
   - Dead walking: while dead, the client opens the `PLAYER_S[0]` dialog on click-to-move instead of walking. The server ignores `udcp` from a dead character (already the case per combat.md "no encounter at HP 0"; verify).
10. **Blood bag** state is `Character.bloodBag: number[4]`. A small fixed array on the character is cheaper than a feature document and is read on every battle end.
    - Gold is spent from `gold` only (legacy "Vàng-priced actions").
    - `useBloodBag` is sent by the client after `battlePlayEnd`. The server ignores it while the session is in a battle or watching.
11. **Visible bosses:** only the loop bosses are shown (Trừ Ma map mode, Trị An item summon). `LOOP_BOSS_QUEST_IDS` stops excluding them from round picks.
    - Go's type-4 "boss" rows are **not** sent (they are crafting nodes).
    - Schedule / world / field bosses (`data_tbl_schedule_boss`, `game_tuning_map_boss`) belong to M10.
    - Trị An's per-round hiding spot (`loop_tri_an_location.go`) and its milestone extras are deferred; the summon works anywhere on a field map (`safeFlag` 0).
    - Air bosses (`layer 3`) are **shown on the ground**, since H5 has no flying yet (the `Bay` button is notReady). Recorded as a deviation.
12. **`hitNpc` / `clickBoss`** are ported generically: an NPC on the player's map, within 300 px, with `data_tbl_npc_creature` rows. They are used by no H5 content until M10, plus a GM/test path. `clickBoss` is an alias, as in Go. No walker (type 25) AI in M9.
13. **Settings gates:** `ag` (team invites), `achat` (private chat) and `at` (trade) are **enforced server-side** in H5 (Go never did), with H5 refusal strings `<name> không nhận lời mời nhóm.` / `<name> không nhận tin nhắn riêng.` / `<name> không nhận giao dịch.` (open question 5).
    - Client-only keys implemented in H5: `hc`, `hn`, `ac`, `maxView`, `battleStExpan`.
    - Shown but inert (no H5 feature): `am`, `he`, `hm`, `dressHide`, `flyEffect`, `hpmf`, `nlws`, `cf`, quality, `bfr`.
    - `Thiết lập lại` sends `us` with every panel key true (no `resetSetting` RPC, it never existed in Go). `Thiết lập chat` is deferred.
14. **`toMovable`** reuses `SceneTransportService.moveToMap(session, map, safe)` and pushes `onSceneEnter`, like revive. The legacy `onSceneTo` / `onCharTeleport` pair is not ported (H5 has no such pushes).
15. **World map** opens from the Earth tray button and the M key. The local MapPanel (`~`, minimap image `mMap`) is deferred.
    - The art is copied from `E:\mcgame\h5\public\img\skin\world\WorldMap1.jpg|WorldMap2.jpg` into `client/public/ui/world/` (a read-only copy out of legacy).
    - The pin table is extracted once into `client/src/ui/worldMap/pins.ts`, from `WorldMap.as:106-720` or the old `h5/src/ui/worldMapSheet.ts:52`.
16. **Help** content is converted once by `server/tools/help-xml.ts` (tsx) into `client/public/help/help.json` `{id, label, html}[]`, with Flash htmlText reduced to `<b><i><u><br><font color>` → safe spans. The GM tab and the forum link are hidden.
17. **Emoji:** the popup sends `say(0, '/code ')`. A received message whose trimmed text is exactly an emoji code shows the animation over the speaker's head for 3 s and is still printed as text in the chat log. No inline icons in the log (Flash has none). The 23 `EM_NORMAL_*` SWFs are converted with `tools/swf` (`swfanim`) to `client/public/sheets/emotion/`.
18. **Spectate:** `startWatch` / `quitWatch` + `onWatch` / `onWatchEnd`, in memory, with the Go gates and strings. The menu item `Xem chiến đấu` sits in the existing player menu, enabled when the target is in battle (state 5).
    - **Replay is deferred** (`getBattleReplay`, `getRecentBattles`, `battleReplayEnd`, `watchBattle`): there is no Flash UI or playable data, and the real replays are M12 pet arena.
19. **No new RPC is `quiet`.** State-changing RPCs are `forbidInBattle` except `useBloodBag`, the relive RPCs and `quitWatch`.

## 10. Risks and open questions
1. **Damage from `exp_skill` on upgraded skills** (decision 4, user keeps the current rule): upgraded rows have
   `exp_skill` up to 5·10⁹, so damage may grow very fast with skill level. Browser-check a few upgraded skills in Phase B
   and report the numbers; the Go description-ratio rule (§2.2) stays documented as the fallback if the user changes it.
2. **expSkill semantics:** deriving the pool from cumulative `exp` (decision 2) means a player at level 20+ who spends exp can no longer `lvUp` until refilling. This matches legacy, but confirm it is wanted.
3. **World-boss map id:** Go code `domainwb.DefaultMapID` = 2006 vs `hinh-nhan.md` "map 47". Only matters when the world boss lands (M10+).
4. **Awakened skills:** Flash shows the `exSid<awakenPoint>` variant and Go accepts it on the hotbar/auto/learn. Does H5's M7 awakening store per-skill awaken points? If not, variants are deferred.
5. **Settings gates `ag` / `achat` / `at`:** enforce them (H5 decision 13, invented refusal strings) or keep them cosmetic like Go?
6. **Watch-mode quit button label:** the Flash BattleStage string was not traced. The implementer reads `BattleStage.as:2654` / Language before inventing `Thoát`.
7. **`GameScene.ts` size:** Phase E must split it (NpcLayer / BossLayer) to stay near the cap; ~430 lines today.
8. **Skill book item type:** confirm `data_tbl_item_template` type 505 rows and that the H5 bag shows them as usable (`useType`).
9. **Help content:** `help.xml` htmlText may embed Flash-only tags or image links; the converter drops unknown tags, which may lose some formatting.
10. **Emoji assets:** the 23 SWFs must convert with `swfanim`. If some fail, fall back to a static first frame.
