# Map Portals (Transport Gates) — Implementation Plan

**Date**: 2026-11-03 · **Status**: Approved
**Goal**: every map shows its transport gates (cổng dịch chuyển) with the original animated portal art. Clicking a
gate walks the player onto it; when the walk ends on the gate, the server moves the player to the paired gate on the
destination map exactly like the legacy game. Today H5 has no portals: maps can only be changed with the `/go` dev
command, and `sceneChange` wrongly takes a map id.

Research base:
- `docs/research/2026-11-03_06_MAP_PORTAL_CLIENT_RESEARCH.md` — Flash client: data, drawing, trigger, RPC.
- `docs/research/2026-11-03_07_MAP_PORTAL_SERVER_RESEARCH.md` — Go server: tables, destination resolve, landing, pushes.
- Legacy Go (read-only, `E:\mcgame`): `internal/application/scene/teleport.go`, `teleport_alias.go`,
  `teleport_landing.go`, `internal/gamedata/sceneitem_gates.go`, `internal/presentation/rtmp/handlers/scene/handler.go:153`,
  `scene/login.go:169-230`.

## 1. Confirmed mechanics

- **Data** (client `GamePredef.as:542-543, 8365` + Go `sceneitem_gates.go:8-21` + seeds): gates are rows of
  `data_tbl_sceneitem_instance` whose template (`data_tbl_sceneitem_template`, `id = instance.tid`) has `type = 3`.
  Templates: 38 传送点 (res 2020040000001, red circle), 98 coffin (…002), 99 入 (…003), 100 出 (…004), 101 tree hollow
  (…005). 154 gate instances. Instance columns used: `id, tid, name` (= destination map name), `pos_map_id`, `pos_x`,
  `pos_y`, `pos_dir`, `layer`, `color_code`, `from` (paired gate instance id, 0 = unpaired). Coordinates are map pixels.
- Samples: map 1 gate 732 "Đông Xuất Vân" (1649,1306) from 733; map 2 gate 733 "Xuất Vân Thôn" (120,63) from 732;
  map 3 gate 758 "Thiện Tĩnh Địa" from 812; map 4 gate 812 "Vân Đài" from 758; map 3 gate 757 "Xuất Vân Thôn" from 0.
- **Drawing** (`SceneItemView.as:49-80`): sprite (0,0) at `(pos_x, pos_y)` = top-left of the SWF stage; alpha 1 when
  `layer == 0`, else 0.6; `pos_dir == 1` mirrors (scaleX -1). Depth uses `pos_y + localizer.y` (SWF child named
  `localizer`). No name label; hover tooltip `"Chuyển đến: " + name` (`SCENEITEMVIEW_S[0]`). Hidden in battle.
- **Trigger** (`SceneItemView.as:72-80`, `PlayerView.as:198-203`): only a click on the gate (type 3) sets it as target
  and walks to the clicked point; when the walk stops and the player shadow hit-tests the gate sprite bounds, the
  client sends `sceneChange(gateInstanceId)`. Walking across a gate without clicking it never triggers. Client
  throttle 1100 ms (`RPCConfig.as:34`). No client level gate.
- **Server `sceneChange(gateId)`** (`login.go:169-230`, `teleport.go:35-111`): no distance/level/state check. Unknown
  gate or unresolvable destination → invalid args. Destination:
  1. `from != 0` and the paired gate exists with `pos_map_id > 0` → land beside the paired gate.
  2. else target map = `gateIDTargets[id]` → `gateNameTargets[name]` → lowest-id map whose `name` equals the gate name
     (`teleport_alias.go:39-68`); land beside the reverse gate on that map, or at the map safe point if none.
  - `landBesideGate` (`teleport.go:94-111`), `gateLandingOffset = 100`, `gateLandingDistance = 180`: (sx,sy) = dest
    map `safe_x/safe_y`, (gx,gy) = gate pos, d = hypot(sx-gx, sy-gy); d < 1 → (gx+100, gy+100); else
    step = min(180, d), (round(gx + dx/d·step), round(gy + dy/d·step)). The fixed table in `teleport_landing.go`
    (~62 gates) overrides the formula. Direction on arrival 0. Position persisted immediately.
  - Legacy reply is null; pushes: old room `onCharLeaveScene`, self `onCreateNpcs`/`onCreateBoss`,
    self `onSceneEnter(mapId, x, y, -1)`, self `onCreateChars`, new room `onScenePlayerEntered`.
- **Gate list RPC**: `createSceneItems()` → every scene item on the caller's map (`world.go:147`); `[]` on copies.

## 2. Shared contract (`packages/shared/src/protocol.ts`)

```ts
/** createSceneItems(): scene items on the caller's map. H5 joins the template (no client gameData tables). */
export interface SceneItem {
  id: number;
  tid: number;
  type: number; // template type; 3 = transport gate
  name: string; // for gates: destination map name
  posX: number; // top-left of the item SWF stage, map pixels
  posY: number;
  posDir: number; // 1 = mirrored
  layer: number; // 0 = opaque, else alpha 0.6
  resCode: string;
}

export const SceneItemType = { TRANSPORT: 3 } as const;

/** onSceneEnter push after sceneChange(gateId) (H5 payload: same shape as the sceneLogin reply). */
export type SceneEnterPush = SceneLoginResponse;
```

- `sceneChange(gateInstanceId: number)` → `null`; then push `onSceneEnter(SceneEnterPush)` to self.
- H5 deviation, kept on purpose: the old/new room broadcasts keep the existing H5 names `onScenePlayerLeft` /
  `onScenePlayerEntered`, and the client keeps pulling `createChars` / `createNpcs` / `createSceneItems` after a scene
  load (instead of `onCreateNpcs`/`onCreateChars` pushes), the same flow `applyScene` already uses.
- `/go <mapId>` (dev command) moves to a new RPC `gmGoMap(mapId)` → `SceneLoginResponse` (the old map-id behaviour of
  `sceneChange`, safe point arrival), so `sceneChange` matches the legacy contract.

## 3. Design

### 3.1 State
No new player state. Arrival position written with `CharacterService.updatePosition` (as today). Gates are static.

### 3.2 Static data
`GameDataService`: cache `data_tbl_sceneitem_instance` + `data_tbl_sceneitem_template` at startup (small tables).
Accessors: `sceneItemsOnMap(mapId): SceneItemRow[]` (joined with template), `sceneItem(id)`, `transportGates()`,
`mapByName(name)` (lowest id). Put the row types and indexes in a new `gamedata/sceneitem-data.ts` (like
`quest-data.ts`) to keep `gamedata.service.ts` under the line cap.

### 3.3 Server
- New pure module `server/src/modules/scene/portal.rules.ts` (+ `portal.rules.test.ts`): `resolveGate(gateId, data)`
  and `landBesideGate(gate, safe)`, with the alias tables (`gateIDTargets`, `gateNameTargets`) and the landing
  override table ported verbatim from `teleport_alias.go` / `teleport_landing.go` (comment each with its Go source).
  Takes a narrow data interface so tests need no Mongo.
- `scene.rpc.ts`: `createSceneItems` (`requireCharacter`) → `SceneItem[]` for `session.mapId` (all items; client
  filters type 3); `sceneChange(gateId)` (`requireCharacter`): validate integer → resolve → `RpcException.invalidArgs`
  when unresolved → broadcast `onScenePlayerLeft` to the old room → persist → `enterScene` → `session.callback(
  'onSceneEnter', [resp])` → return `null`. `gmGoMap(mapId)` = old sceneChange body (map id + safe point).
  If `scene.rpc.ts` passes ~300 lines, move the portal RPCs to `portal.rpc.ts` in the same module.
- Dungeon gate guard: not ported (non-goal).

### 3.4 Assets (`tools/swf`)
Gate SWFs (`resource/item/SITEM_SPAWN_00000{1..5}.swf`) are vector with nested animated sprites (main timeline 1 frame),
182x136 / 349x171 / 245x205; not in the sheet manifest. Add `swfanim` to `tools/swf`:
- Extend `SymbolLibrary` (`src/sheet/compose.ts` / `src/swf/display.ts`) with a frame-indexed render: render the main
  timeline where every nested sprite shows frame `globalFrame % sprite.frames.length`.
- `swfanim -cache DIR -out DIR [-frames N] <md5|file>`: N = max nested sprite length (cap 120) unless given; writes
  the standard sheet format (`SheetData`: one image per frame, anim `default`, identity matrices offset so (0,0) is the
  SWF stage origin, `fps` from the SWF) and `meta.localizerY` when a child named `localizer` exists (instance name in
  PlaceObject2/3). Output `client/public/sheets/item/SITEM_SPAWN_00000N.{png,json}` and add manifest entries
  (category `vector-anim`). Document in `docs/assets-pipeline.md`.

### 3.5 Client
- New `client/src/game/PortalLayer.ts`: after each scene load call `createSceneItems`, draw type-3 items with
  `loadSheet(sheetNameFromResCode(resCode))` + `SheetAnim` looping `default`, at (posX, posY), alpha/mirror per §1,
  zIndex `posY + localizerY` in `entityLayer`; hover tooltip "Chuyển đến: <name>" (DOM title-like label or Pixi text
  shown on hover). Click → `GameScene` walks to the clicked map point with the gate as `pendingGate`; on arrival, if
  the self position is inside the gate sprite bounds → `sceneChange(id)` (throttle 1100 ms). Any ground tap clears it.
- `GameScene`: `onSceneEnter` handler → `applyScene(resp)`; `applyScene` also loads portals; clear on scene change.
- `sceneCommands.ts`: `/go` calls `gmGoMap`.

## 4. Non-goals

- Dungeon gate guard (`gate_guard.go`): dungeons are not ported; no dungeon map has reachable gates in H5 yet.
- Group followers teleporting with the leader: no groups yet.
- Minimap panel gate icons (`MapCanvas.addIp`): the map panel is not ported.
- Loading modal/fade on map change: unproven for portal travel; the current scene reload stays.
- `onCreateNpcs`/`onCreateChars`/`onCharLeaveScene` push names: H5 pull flow already covers it (see §2).
- Non-gate scene items (decorations, houses, trees): drawn by nothing yet; only type 3 is rendered.
