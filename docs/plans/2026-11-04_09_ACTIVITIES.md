# Activities (M8): activity strip, daily systems, VIP, loop quests, bosses and small features — Implementation Plan

**Date**: 2026-11-04 · **Status**: Approved (2026-11-04; the user pre-approved M5–M8 plans and asked for autonomous execution with one commit per milestone)
**Goal**: the daily-retention layer:
- the HUD activity icon strip;
- daily sign-in (5-day and the monthly calendar);
- the activity diary with point chests;
- the online-time gift; offline exp;
- the tutorial guide log;
- VIP (PM) levels with daily rights and the VIP shop;
- loop quests (Trị An, Trừ Ma, 200 vòng, guild loops…);
- the daily boss; festivals;
- small stores: lotto / wish tree, prabuff, mount.

Today none of this exists, apart from a `loopInfo` stub in the login payload.

Delivered in **four phases**, each implemented, lint/test-verified and browser-checked before the next:
- **A**: activity strip, sign-in, diary, online gift, guide log.
- **B**: VIP / PM and the VIP shop.
- **C**: loop quests and the importer fix.
- **D**: daily boss, offline exp, festivals, lotto, prabuff, mount.

Research base (the implementer reads both):

## 1. Decisions (H5)
1. **Timezone**: all day/week/month keys are computed in **UTC+7** (Asia/Ho_Chi_Minh, the legacy server timezone), with one shared helper with tests.
2. **Rewards without content data**: the diary chests (items 3255–3259, per `icon_giid`; Go's 2003–2007 were wrong), the sign-in day bags 4135–4138 and the online gifts have descriptions but no contents table.
   - *(H5)*: grant **exp and bound silver scaled by level** directly: `BASIC_GET_EXP[level] × k` and `BASIC_GET_MONEY[level] × k`, with a per-reward `k` in one documented table in shared.
   - Description text that names a concrete existing item is honoured.
   - Every choice is recorded in the plan notes.
3. **Loop-quest rewards**: the data has none, so the Go class-quest formula (`gamedata/predef/quest_reward.go`, BASIC_GET_EXP/MONEY) is applied per round, and also per completed loop if Go has a loop-end reward.
4. **PM right 1** (daily exp): capped at one level's exp (`LEVEL_EXP[L+1]-LEVEL_EXP[L]`); Go's multiplier gave 2–9 levels a day.
   - Rights 1, 2, 3, 7, 10, 13 and 24 (findback) have real rules; the other rights are display only (Go).
   - Progress is marked **before** the reward is applied (Go double-paid on a crash).
5. **VIP shop**: port the simplified version over shop 99 (71 slots), using the weight column `r` for the rotation.
   - `getVipShopConfig`, `getVipShopCharConfig` (refresh 20 gold), `buyVipShopItem(slotId, num)`; requires `pmLevel > 0`. Go-invented constants are recorded.
6. **Gold top-up does not exist** (user decision): `buyPm` spends existing gold. Gold comes from `gmGrant` / mongosh for testing.
7. **Importer**: fix the case-sensitive `insert into` regex in `server/tools/import-seeds.ts:33`.
   - The implementer re-runs `pnpm import:seeds` only if it is idempotent; it says so, and lists which tables appear (e.g. `data_tbl_schedule_boss`).
8. **Deferred** (no data or Go logic, or needs systems H5 lacks):
   - gift codes; nine boss; consume/recharge/guild-war events; quiz and maze;
   - marriage; pet arena; pet PVE tower; dress gacha and runes; farm and estate;
   - life skills (cook, medicine, gathering); boss loot; schedule / world boss display;
   - the Trị An / Trừ Ma boss rounds (they need `onBossOn`/`createBoss`).
   - Tutorial guide: only `saveGuideLog` persistence (the step engine points at panels H5 lacks).

## 2. Confirmed mechanics (summary; rules with file:line in the research docs)
- **Activity strip**:
  - `startedActList` comes from `data_tbl_activity` (84 ids), with `type` gating: 0 flag, 2 level ≥ flag, 3 state label, 4 `expRe > 0`.
  - Layout: width 450, 48×48 icons, 2 rows × 8 per tab, paged, sorted by `sortType` then id, and a red dot until clicked.
  - Icons for unported systems are hidden.
- **Sign-in**:
  - The legacy 5-day panel: `getSignInData` / `signinNow` → `{continueSigninTime, signinedToday, signedYesterday}`.
  - The monthly calendar: `initDailySignInActData`, `dailySignInActDoSignin`, `dailySignInActGetAward`, `dailySignInActRetroactive` (50 gold), `dailySignInUpActCrit` (100 gold), plus the crit meter, the Saturday surprise, the Thursday lucky claim and the level-50 gate.
  - The lucky-day tiers exist only for May 2026, so the claim is dead in other months (record it).
- **Diary**:
  - `getCharDiaryData` → id→count plus `act` and `ad`; push `updateDiaryData(id, val, act)`. Chests at 30/60/120/210/360 points, claimed via `getDailyActAward`, one claim per day across tiers (`ad` flag).
  - Hooks wired in H5 for: login (29), online 30 min (33), party create/join (34), loop finishes (19, 17, 20, 3, 4, 5) and the 200-vòng milestones (13–16).
  - The other tasks have no source and are recorded.
- **Online time**:
  - `getTodayOnlineTime` → `{t, f}`. *(H5)*: real session time accumulated per day (Go used wall-clock since the first login).
  - A gift every 30 min via `getDailyOnlineAct`: -1 re-init, > 0 minutes left.
- **Offline exp**:
  - `getOfflineExp` / `getPetOfflineExp(type, hours)`: rate `BASIC_GET_EXP[level]` × [0.3, 1, 2, 3] by mode, level ≥ 30.
  - Costs and the error codes -2..-9 with their strings per the research.
  - The login carries the `offlineTime` key.
- **VIP / PM**:
  - `initPmData` → `{flag (pmLevel), date, findback, processFlag, data{pmExp, activeType, keepDay, activeTime}}`.
  - `buyPm(1|2|3)` costs 688 / 1688 / 2888 gold for 30 / 90 / 180 days; a downgrade is refused while active.
  - pmLevel = max(level from pmExp, vipType), clamped 1–9; thresholds `[0, 15000, 45000, 105000, 205000, 355000, 555000, 805000, 1105000]`.
  - Daily login PM exp: 500 / 1000 / 2000 by type. `doPmOperation(rightId)`.
- **Loop quests**:
  - 7 live loops (lids 2, 4, 5, 6, 7, 9, 16; others need `min_level` 200 and are disabled).
  - `takeLoop(lid, npcId)`, `cancelLoop(lid)`, `loopRepaire(lid)`; pushes `onCancelLoopQuest {flag, id}`, `onFinishLoopQuest {id, ft}`; `loopInfo.d[lid].canTake` gates the NPC "[Vòng]" entries.
  - Rounds use the existing objective types; rounds that need boss summons are skipped/re-rolled (record).
  - The take cooldown is anchored at take time + `refresh` (Go). Uniform random round pick; no vigor or silver cost.
- **Daily boss**:
  - 79 configs. Type 1 allows 2 or 4 attempts a day; type 2 has a 72 h cooldown; attempts are consumed at battle start.
  - `bossDailyGetData` / `bossDailyBattle` start a normal PvE battle against the boss creature; `bossDailyFinishByCard` is a check only.
  - Rewards: battle exp (no loot data).
- **Festivals**: the 32 `data_tbl_feast` rows (`aw` = a gift-bag item id, `at` = a schedule string, months 0-based). `getCurrentFeast`; `takeFeastGift` has no Go handler, so it is an H5 rule: the gift once per feast, with the bag contents resolved like decision 2.
- **Lotto / wish tree**: `TBL_PLAN` weighted rolls (Go). **Prabuff**: tracks from the client constants; Go-assumed costs recorded. **Mount**: 5 RPCs plus riding (`beginMounting`/`stopMounting`, `onMountOn/Off` broadcast, `mountInfo` at login); the mount stats go through a stat provider.

  - Keep `GameScene.ts` / `BattleController.ts` from growing.

**Decisions / deviations**
- **Ported ids**: the strip only lists ids 0 (daily activity) and 65 (sign-in) (`ACTIVITY_PORTED_IDS`; later phases add 19, 49, ...). Icons are labelled tiles (the Flash `Btn*` skins are CSS art, not extracted). The red dot shows on every icon until clicked (Flash only dots icons added after the first list).
- **`updateActivityList` / `updateActivityState`** are handled by the client but never pushed in phase A (no dynamic type-3 entry is ported). Names are the Go ones, unconfirmed in Flash.
- **H5 catalog RPC `getDiaryList`** (TBL_DIARY rows); the Flash client read its static table.
- **Timezone**: every day / week / month key is UTC+7 through `@mc/shared` `dayKey`; the old achievement `dayKey` (server local time) was left untouched.
- **Sign-in**: one ledger (`character_signins`, month bitmap) for both panels; the client shows them as two tabs of one window (the 5-day panel has no opener in the strip data). `signinNow` (level 20) pays the card of the streak position (the items named by the Flash text are resolved by name and granted bound, plus level-scaled exp / silver); `dailySignInActDoSignin` (level 50) pays the calendar pools. Both mark the same day, so one sign-in per day in total. The 5-day streak crosses month boundaries. `dailySignInActDoSignin` replies inline and pushes only `setBtnsDailySignInAct` (Go also pushed `onDailySignInActDoSignin`; H5 pushes that one for the retroactive sign, which has no inline reply). Failed gates throw `RpcException.forbidden` with the text (the client toasts it).
- **Calendar rewards** (decision 2): the 3 Go reward rows (items 408 / 4015 / 4080) are placeholders and ignored; `calDaily` / `calSurprise` / `calCrit` pay exp + bound silver by level. `iInfo` is empty. Lucky claim pays regular gold by tier and stays closed in every month but May 2026 (no tier rows).
- **Diary**: counts are clamped to the table `max` (Go never clamped). Hooks wired: login (29), 30 online minutes (33, derived from the day's online time by the 60 s ticker) and party create / join (34). Unsupported tasks: all others, recorded for phases C / D.
- **Chests** (items 3255..3259): their description is parsed ("Có thể mở ra: ..." pool, "Chắc chắn nhận: ..."); two pool items are picked at random, names with no template (Pha Lê Ma Pháp, some pool entries) are skipped and logged, plus level-scaled exp / silver. A full bag refuses before the one-per-day mark; the mark is written before anything is credited.
- **Online time**: real session time per UTC+7 day (flushed every 60 s and on disconnect / back to char select, split at midnight). Gift: every 30 min via `getDailyOnlineAct` (-1 re-init, > 0 minutes left, 0 after 48), exp + bound silver (`REWARD_K.online`), compare-and-set on `giftsClaimed` before crediting.
- **Guide log**: `saveGuideLog(id)` writes `character_features` key `guide`; the login carries `guideFlag`. No step engine.
- **GameScene.ts** grew by 3 lines (import, field + construction, destroy list); everything else is in `ActivityController`.
- Static tables are read through `GameDataService.rows()` from `ActivityDataService` (cached) instead of adding accessors to the 470-line `gamedata.service.ts`.
- k table values (`REWARD_K`) are my picks; tune in `rewardScale.ts`.

**Files**

- Server `modules/vip/`: `vip-core.module.ts` + `pm-state.service.ts` (document, rights cache, pmLevel lookup, scene decoration; imported by chat and scene), `vip.module.ts`, `pm.service.ts` / `pm.rpc.ts`, `pm-reward.service.ts`, `pm-rules.ts` (pure), `vip-shop.service.ts` / `vip-shop.rpc.ts`, `vip-shop-rules.ts` (pure), schemas `character_vip`, `character_vip_shop`. - Client: `ui/vipPanel.ts`, `ui/vipShopView.ts`, `ui/vip.css`, `game/VipController.ts` (owned by `ActivityController`); the HUD VIP button opens the window and shows `VIP<n>` (grey when 0); strip icon 19 opens the shop tab. `GameScene.ts` unchanged in length (two existing lines extended).

**Decisions / deviations**
- **pmLevel 0** = no active membership (Flash: 0 / absent is not a member); expired members keep `pmExp`. `buyPm` takes gold from `gold` only (Go), spends first, refunds if the membership write fails; the write is a compare-and-set on `rev`.
- **pmExp on purchase** = `max(pmExp + cost, PM_EXP_THRESHOLDS[type - 1])` (Go's array index is unclear; this reading keeps "a card lifts you to its level"). Renewal / upgrade extends from the current expiry, `activeTime` stays the period start; `keepDay` = (expiry - start) / day.
- **Daily login PM exp** is lazy at login (`loginFields`), marker `dailyExpDay` (UTC+7); Go's `addOrMinusPmExp` push is not sent (the login payload and `initPmData` carry the exp).
- **Claims**: progress `{day, type, time}` is marked with a CAS BEFORE the reward; a full bag refuses before the mark. Cycle keys: daily = day key, `2|30` = month key, `2|7` = week key. `initPmData.processFlag` lists only current-cycle entries (the Flash panel would show stale cycles as claimed). `doPmOperation` errors are `RpcException.forbidden` (client toasts) instead of Go's `onSystemSay`.
- **Right 1**: `min(one level's exp, BASIC_GET_EXP[level] * value)`, i.e. one level at most (decision 4). **Right 2**: `goldBind += value` (`onAddMoney` + `onUPP`). **Right 3**: buff `2504..2510, 3308, 3309` via `BuffService.grant` lasting until the next UTC+7 midnight (Go: permanent, never refreshed). **Right 7**: item 3630 x value (level 4+). **Right 10**: bag `3231 + min(level, 7)`, monthly. **Right 13**: daily pick from `data_tbl_creature show_able = 1` res codes (84), persisted in `character_vip.transform`; `onSetRes {id, res}` pushed to the caller and the map, and scene payloads (`createChars`, `onSceneEnter`, `onScenePlayerEntered`) use the code as `resCode` until the next UTC+7 midnight. The client has no live `onSetRes` handler (visible on the next map entry). Rights 18 / 25 (open a panel) are client-only and display-only here; every other right is display only.
- **Findback (right 24)** differs from Go (which only cleared the flag): a daily audit (lazy, once per UTC+7 day, only for levels where right 24 is enabled, level 4+) records yesterday's unclaimed recoverable rights `[1, 2, 7]` (the buff / transform are day-bound, the bag is monthly); the claim pays one catch-up of those rights and clears the flag first. A gap of several days counts as missed.
- **VIP shop** (shop 99, 71 visible slots): Go-invented constants kept: 6 slots per 4-hour rotation (UTC+7 aligned), discount `[0,2,4,8,12,18,25,33,42,50]%` by pmLevel, personal refresh 1 free then 20 gold, 5 a day, gold only (never bound), item unbound. H5 additions: the rotation is a weighted draw by the slot `r` column (seeded by the rotation index; Go ignored `r`), a purchase is marked per slot BEFORE the charge (CAS) and unmarked on failure, refresh keeps this rotation's purchase marks, `num` is accepted but forced to 1, `shopDynamic` is always `[]` (no live feed). Non-members get a forbidden error ("Chỉ có VIP mới có thể sử dụng Shop VIP!"). Reply carries `refreshLeft`, `refreshCost`, `discount` extras.
- **pmLevel gates in H5**: the server enforces only the VIP shop, the claims and the displayed `pmLevel` (chat, scene). The Flash client gates (auction >= 3, pet soul, lottery, card-game bonus, fusion rate bonuses) belong to features not ported yet; nothing to wire.
- Not done: head badge image (`PM_ZUAN`), gem-exchange / star-exchange openers (rights 18 / 25), `updateScenePmLevel` display on other players' name labels (the push is handled for self only), PM exp bar frames (a plain bar), the Go `onBuyPm` / `onAddPm` pushes (the reply carries the data).

No `quest_history`. Pet exp and `questsFinished` achievement follow the normal path. Push order: normal finish pushes, `onFinishLoopQuest {id, ft}` (H5 adds `num`, `name`; `num = ft` when the cycle ends early), next `onAddChaQuest` + its accept-time item.
- **Diary**: lids 2/4/5/6/7/16 feed tasks 5/19/20/3/4/17 once per round; lid 9 at ft 50/100/150/200 also feeds 13..16 (DiaryEvents clamps to the table cap).

- Not done: the Flash loop tab of the quest manager, `getLoopQuestStartTime`, team gating (Go ignores `team`), the boss rounds, lid 2 chests / lid 4 crystal text rewards. The cooldown is not displayed (the refusal text says to wait).

**Decisions / deviations**
- **Daily boss**: solo (the Go server is solo too); `total 16` is enforced (Go never did). The attempt is persisted before the battle starts and refunded if the start races. `dfd` is set at start (Go), so `bossDailyFinishByCard` is check-only. Enemies = the `npc_creature` group of the boss (main first, levels kept); battle exp = row exp. Seed levels of 2265..2268 are -2: the main row level (155) is shown. Strip icon 49.
- **Offline exp**: bank in `character_features.offline {bank, leftAt}`; `leftAt` is written on disconnect / back to char select, an unclean exit (server restart) gives no offline time. `offlineTime = min(3 days, bank + time since leaving)` at login (the cap is an H5 choice). Pet exp goes through `PetBattleService.grantQuestExp` (no life drain). Code -7 is defined with its string but never returned (Go never returns it; the panel text says level 30+ may use every mode). The button is the HUD "Ủy thác" (no strip id exists).
- **Festivals**: `at` order is hours|weekday|day|month (0-based), confirmed by the 32 rows. A bag-named gift (`Túi Quà`, `Rương`) pays exp + bound silver (`REWARD_K.feast`); any other gift item is granted itself as well. The strip icon 25 (type 3, state 2) is added at login only while a feast is active (no mid-session `updateActivityState`). No row is valid on 2026-11-04, so the browser test used a temporary `data_tbl_feast` row (id 99) that was deleted afterwards; the unit tests inject the clock.
- **Lotto**: pool = plan rows of type t with `ti` 29 / 19 and no quest id (other tables cannot be granted); templates are validated at roll time (re-roll). Costs and the free first wish are Go display constants. Entry through strip icon 21 (disabled in the seed, forced on); no VIP gate (the Flash LotteryPanel has one, the wish tree panel does not). Only the `lotto` bag is ported (not lottery / luckDraw).
- **Prabuff**: tables from the client constants; tracks 1, 3, 5, 7 feed `finalReduceHurt1`, `finalReduceHurt2`, `finalEnhPhyHurt` and a speed percent, the pet tracks 2, 4, 6, 8 are levelled but have no effect. The rebirth gate is replaced by level 50 (client strip gate and server). Costs (10 element / 7 gold) and the 10 % x2 crit are Go-assumed.
- **Mount**: gate level 50 for every mutating RPC and `checkHaveMount` (Go: class rank). Skin ids: rank skins are permanent, timed skins via `renewMount` (30 days, extends from the current expiry, only skins with a gold price). Stats while riding = evolution row percents + skin percents through the provider. `beginMounting` / `stopMounting` broadcast `onMountOn` / `onMountOff` to the map and persist `useDress`.
- **Mounted sprite**: the mount `res_code`s resolve to sheets (9 of 18 exist) but each is a ~1600 x 31000 px atlas, over the GPU texture limit (it renders as a black quad). `Entity.swapRes` therefore falls back to the normal sprite for oversized sheets; the scene payloads are NOT decorated with the mount res code (tried, removed). A tools/swf change to split tall atlases is needed before riders can be drawn.
- Not done: festival warn icon (`WARN_TYPE_FEASTIVAL`), the Go `onEndFeastivalDay`, gift-code / login-award RPCs, party daily boss, the lottery / luckDraw bags.
