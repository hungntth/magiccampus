# NPC Talk (click NPC → dialog) — Implementation Plan

**Date**: 2026-11-03 · **Status**: Approved (2026-11-03, user chose legacy display behaviour)
**Goal**: clicking an NPC on the map walks the player next to it and talks to it: talk-only NPCs say
their greeting in a speech bubble (as in the Flash client), function NPCs (shop, heal, bank, …) open
the "Đối thoại" dialog with portrait, name, greeting text and the function button. Today an NPC click
is swallowed by the stage tap handler and only moves the player; there is no NPC RPC on the server.

## 1. Confirmed mechanics

- **RPC `clickNpc(npcId: number)`** — client → server; `npcId` = NPC id (= `data_tbl_npc._id`). Legacy
  returns nothing; the answer is a **push**. Legacy server has no map/distance/cooldown check; the
  client rate-limits to 1 call / 1100 ms (`RPCConfig.as:50`).
- **Push `npcFuncInit(payload)`** (legacy `npc_interaction.go:124-134`, read at `NpcFuncPanel.as:757-835`):
  `{ npcId, npcName, npcType, npcQuest: { npcId, state, list }, loopInfo: { d, flag } }`.
  - `npcType` = the NPC row `type` only if it is one of the function types
    `{2 Shop, 5 Auction, 7 Bank, 8 Heal, 9 Transport, 13 Callboard, 16 Tutor}`, else `0`.
  - `npcQuest.state` = `-1` when the NPC has no quest for the player (102 can-take, 103 in progress,
    104 can-finish otherwise); `list` keyed by quest id. `npcQuest` is always present.
  - `loopInfo` default `{ d: null, flag: false }`.
- **Greeting text** = `data_tbl_npc.on_service_text` (nullable). The Flash client reads it from its own
  static NPC table; the server never sends it. Examples (map 1): 231 "Trưởng Thôn Stoff", 240 "Tân Thủ
  Sứ", 455 "Vệ Sĩ Xuất Vân" (type 1, long Vietnamese lines); 409 "Y Tá Loli" type 8; 239 shop type 2
  `shop_id 4`.
- **Client click flow** (`NPCView.clickNpc`): ignore type 25 (WALK); ignore when dead / not in normal
  state; if distance player→NPC > **250 px** → walk toward the NPC, and on stop within 250 re-run the
  click; then face each other and send `clickNpc`. Type 15 (BOSS) uses `clickBoss`, battle NPCs use
  `hitNpc` (combat), 27/28/29 are client-scripted minigames — none of these send `clickNpc`.
- **Dialog** (`NpcFuncPanel`): title "Đối thoại"; NPC icon + `npcName`; text `onServiceText`; quest rows;
  one function button labelled by type — 2 "Shop", 5 "Rao bán", 7 "Kho", 8 "Trị liệu", 9 "Dịch chuyển",
  13 "Bảng thông báo", 16 "Sức sống" — hidden when `npcType <= 0`; close button "Rời khỏi". No
  distance-based auto-close was found.
- Legacy: an NPC with `npcType <= 0` and no quests shows `onServiceText` as a **speech bubble** over the
  NPC instead of opening the panel; `npcType > 0` with no quests jumps straight to the function.
- Function button → `npcFuncClick(npcId)` (shop/bank/auction…) or the client-side heal/transport/tutor
  panel then `npcFuncOther(npcId, funcId)`. Out of scope here (see §4).
- Nothing is persisted on click; the legacy `TalkToNPC` quest hook has no callers.

## 2. Shared contract

Add to `packages/shared/src/protocol.ts`:

```ts
export const NpcType = {
  QUEST: 1, SHOP: 2, MAIL: 3, PLAN: 4, AUCTION: 5, SKILL: 6, BANK: 7, HEAL: 8, TRANSPORT: 9,
  BATTLE: 10, CLASS_QUEST: 11, MAT: 12, CALLBOARD: 13, ANSWER: 14, BOSS: 15, TUTOR: 16, GUILD: 17,
  BUILD: 18, STORY_BATTLE: 19, QUEST_BATTLE: 20, FISH_POOL: 21, PLANT: 22, HERB: 23, GATHER: 24,
  WALK: 25, SYNCHRO: 26, HULA: 27, DOTA: 28, TRIPLE_TOWN: 29,
} as const;

export interface NpcQuestEntry {
  id: number;
  qid: number;
  name: string;
  state: number; // 102 can take · 103 in progress · 104 can finish
  type: number;
}

export interface NpcFuncInit {
  npcId: number;
  npcName: string;
  npcType: number; // function type or 0
  npcQuest: { npcId: number; state: number; list: Record<string, NpcQuestEntry> };
  loopInfo: { d: unknown; flag: boolean };
  // H5 extension: the Flash client read this from its static NPC table; we have no client copy.
  onServiceText: string;
}
```

`SceneNpc.subType` becomes `string` (raw `sub_type`, e.g. `"-1"`, `"13|1720|1721"`, `"all"`); today
`Number()` turns pipe lists into `NaN`.

## 3. Design

### 3.1 State
None persisted. No schema change.

### 3.2 Static data
`GameDataService.reload()` also builds `npcsById: Map<number, Row>` from the `data_tbl_npc` rows it
already loads; add `getNpc(id)`. Fix `toSceneNpc.subType` to `String(row.sub_type ?? '')`.

### 3.3 Server — new `server/src/modules/npc/`
- `npc.service.ts` — `buildFuncInit(npc: Row): NpcFuncInit`: `npcType` per the function-type set,
  `npcQuest = { npcId, state: -1, list: {} }` (quests come with the quest port), `loopInfo =
  { d: null, flag: false }`, `onServiceText = String(row.on_service_text ?? '')`.
- `npc.rpc.ts` — `@Rpc('clickNpc', { requireCharacter: true })` (not quiet):
  validate `npcId` integer → `invalidArgs('npcId')`; `getNpc` missing → `notFound('npc')`;
  NPC not on `session.mapId` → `notFound('npc')` (H5 hardening; legacy had no check, harmless because
  the client only clicks visible NPCs); then `session.callback('npcFuncInit', payload)` and return `null`.
  No distance check (legacy has none; client enforces 250 px).
- `npc.module.ts` — imports `GameDataModule`; add to `app.module.ts`.

### 3.4 Client
- `Entity`: for `kind === 'npc'` set `eventMode = 'static'`, `cursor = 'pointer'`; expose the NPC
  `type` (pass `SceneNpc.type` in). `GameScene` subscribes to the entity's `pointertap`, calls
  `e.stopPropagation()` so the stage tap does not also move the player, then `onNpcClick(entity)`.
- `GameScene.onNpcClick(npc)`:
  - type `WALK`, `BATTLE`, `STORY_BATTLE`, `QUEST_BATTLE`, `BOSS`, `HULA`, `DOTA`, `TRIPLE_TOWN` →
    toast "Tính năng đang phát triển" (combat/minigames not ported), no RPC.
  - distance > 250 → walk to the point on the segment player→NPC that is 120 px from the NPC
    (snapped with `hitMask.nearestWalkable`, sent with `sendPosition` like a normal tap); on arrival
    re-run `onNpcClick` (same as `PlayerView.stopWalk`). A later tap on the ground cancels the pending
    NPC (clear `pendingNpc` in `onTap`).
  - within 250 → player faces the NPC, client-side 1100 ms throttle per NPC, `call('clickNpc', id)`;
    errors → toast.
- Push `npcFuncInit` handled in `bindCallbacks` (legacy `NpcFuncPanel.as:778-835`, user-approved):
  - quest state `<= 0` and `npcType <= 0` → **speech bubble**: `npcEntity.say(onServiceText)` — a Pixi
    bubble above the NPC's name (word-wrapped ~220 px, dark rounded background, auto-hides after
    5 s, replaced by a newer line); nothing when the text is empty. No panel.
  - otherwise (`npcType > 0`, or quests once ported) → `NpcDialog.show(payload, npcEntity)`.
    Deliberate deviation: legacy jumps straight into the function when `npcType > 0` and there are no
    quests; since functions are not ported we show the dialog with the function button instead.
- New `client/src/ui/npcDialog.ts` (`NpcDialog` class, DOM in `#ui`, styles in `style.css`):
  title "Đối thoại", NPC portrait (`iconUrl(iconCode)`), name, `onServiceText` (or "…" when empty),
  function button labelled from the table in §1 when `npcType > 0` → toast "Tính năng đang phát
  triển" (H5 placeholder until shop/heal/… are ported), close button "Rời khỏi". One dialog at a time;
  re-clicking another NPC replaces it; closed on scene change/destroy. Also closes when the player
  walks more than 300 px away from that NPC (H5 convenience; legacy had none).

## 4. Non-goals

- Quests in the dialog (`npcQuest.list`, take/finish) — needs the quest module; payload shape is
  already in place (`state: -1`, empty list), so adding quests later is additive.
- Function panels: shop (`npcFuncClick`, direct-shop NPCs), bank/auction password, heal/transport/tutor
  (`npcFuncOther`), callboard — each is its own feature; the button shows a placeholder toast.
- Hard-coded legacy NPC scripts (`onList`/`npcScript` for ~60 special NPC ids, teleport NPC 1287) —
  per-NPC content, port case by case later.
- Combat NPCs (`hitNpc`/`clickBoss`), minigame NPCs (Hula/Dota/TripleTown), group-leader rule, `busy`
  NPCs, `at` display windows — no combat/groups/minigames exist yet.
