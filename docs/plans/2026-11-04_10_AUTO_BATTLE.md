# Auto Battle — Implementation Plan

**Date**: 2026-11-04 · **Status**: Approved (user, 2026-11-05)
**Goal**: the player can configure "Tự động chiến đấu" (heal/MP thresholds, heal-teammate, heal-pet, default attack skill,
auto-defence, for the character and the active pet), toggle Auto on the HUD or with the in-battle "Auto" button, and battles
then play themselves round after round (character + pet commands chosen by the legacy priority chain) until "Kết thúc auto".
Today the in-battle Auto button and the HUD Auto box are disabled, the minimap "Auto" button shows a toast, no settings are
persisted, and PvE battles end as a loss at round 30.

Research base:
- `docs/research/2026-11-04_17_AUTO_CLIENT_RESEARCH.md` — Flash `Battle.battleAuto/battlePetAuto` chains, `BattleSettingPanel`, strings, keys.
- `docs/research/2026-11-04_18_AUTO_SERVER_RESEARCH.md` — Go `skillSetBattle` / `uif` / `us`, `interfaceData` defaults, -110, round cap.
- Legacy `E:\mcgame\docs\memory\battle-combat.md` § "Unlimited battle auto (client patch, 2026-10-24)" — auto counter made unlimited.

Legacy repo path: `E:\mcgame` (CLAUDE.md says `D:\mcgame`; the checkout lives on E:).

## 1. Confirmed mechanics

- **Auto is client-side.** Both Flash (`Battle.as:94`, `:353`) and Go agree: the client picks normal commands
  (ATTACK -10, DEFENCE -20, SKILL -50, ITEM -60) from the settings and sends the ordinary `battleUpdateCmd`. The Go server has
  no auto brain, no VIP gate, no round cap for auto. -110 (AUTO) on the server is a plain attack (`turn_executor.go:47`).
- **Map-side auto does not exist in Flash** (no auto-hunt / auto-path; "Tự động tìm đường" is a dead string). Out of scope.
- **Round counter**: Flash used 150 rounds; the legacy project patched it to unlimited ("Auto hiện tại còn lại ∞ lượt.").
  We follow the patched behaviour: unlimited until the player stops it.
- **Persistence across battles**: auto stays on between battles (state on the client), lost on relogin (not persisted).
  When auto is on at battle start, the banner shows and round 1 is chosen automatically.
- **Settings keys** (flat `interfaceData`; odd slot = character, even slot = pet; `bt` = 52 skill | 29 item, only slots 1-6):

  | Key | Meaning | Side |
  |---|---|---|
  | `bs1`/`bt1`, `p2` | self HP heal (skill or item) below HP% `p2` | character |
  | `bs9`, `p3` | MP item below MP% `p3` (item only) | character |
  | `bs3`/`bt3`, `p4` | heal first own-side character below `p4` | character |
  | `bs5`/`bt5`, `p5` | heal first own-side pet below `p5` | character |
  | `bs7` | default attack skill (0 = basic attack) | character |
  | `bs2`/`bt2`, `p6` | pet self HP heal below `p6` | pet |
  | `bs10`, `p7` | pet MP item below `p7` | pet |
  | `bs4`/`bt4`, `p8` | pet heals first own-side character below `p8` | pet |
  | `bs6`/`bt6`, `p9` | pet heals first own-side pet below `p9` | pet |
  | `bs8` | pet default attack skill | pet |

  Defaults: `p2..p9 = 10`, `bt1..bt6 = 0`, `bs1..bs10 = 0`. Auto-defence checkboxes (`BATTLE_AUTO_DEFENSE_PLAYER/PET`) are
  client-only, not sent to the server (we keep them in localStorage).
- **Character chain** (stop at the first step that yields a command): 1 self HP (`bs1`, skill: tid = random enemy if
  targetType 4 else self; item: own slot, skip step if no item in bag) → 2 self MP item (`bs9`) → 3 team heal (`bs3`, first
  alive own character under `p4`) → 4 pet heal (`bs5`, first alive own-side pet under `p5`) → 5 auto-defence → 6 attack skill
  `bs7` with MP check (short → toast `MP của nhân vật không đủ,hãy bổ sung!` and fall through); skill type 1 (close) from the
  back row targets a random front enemy → 7 basic attack on a random enemy (random front enemy when in the back row).
- **Pet chain**: mirror with `bs2/p6`, `bs10/p7`, `bs4/p8`, `bs6/p9`, pet auto-defence, `bs8` (toast `MP của pet không đủ,hãy bổ sung!`).
- **Send timing**: commands go out no earlier than 4000 ms after the previous playback started (already enforced by
  `BattleController.transmit` / `SEND_DELAY_MS`).
- **RPCs** (Go `auth/interface_settings.go`):
  - `skillSetBattle(skillId, level, slot, isPet)` — slot arrives as a numeric string; character slots 1,3,5,7 need an owned
    skill; pet slots 2,4,6,8 need an active pet whose slots contain the skill; writes `bt<slot>=52`, `bs<slot>=skillId`.
    `skillId = 0` clears the slot (H5 extension for the picker's "Bỏ trống").
  - `uif(key, value, isPet)` — `btN` (29 for items), `bsN` (item template id), `pN` (0-100). Go stores any key unvalidated; we
    whitelist. `apvp` keeps its current meaning.
  - Login: flat `interfaceData` = defaults ∪ character bucket ∪ active pet bucket.
- **Strings**: panel `Tự động chiến đấu`; headers `Thao tác nhân vật`, `Thao tác pet`, `Kỹ năng tấn công`; slot labels
  `Phục hồi HP`, `Phục hồi MP`, `Pet hỗ trợ` (Flash uses this same label for slots 3/4 and 5/6; keep it),
  `Tự động phòng ngự`; hint `Chọn kỹ năng đánh mặc định\n Để trống là tấn công thường`;
  banner `Auto`, `Auto hiện tại còn lại ∞ lượt.`, stop button `Kết thúc auto`; HUD box `Auto\nbật` / `Auto\ntắt`, tooltip
  `Nút tự động chiến đấu`; minimap `Auto` opens the panel.

## 2. Shared contract

New file `packages/shared/src/autoBattle.ts`, re-exported from `index.ts`:

```ts
// Auto-battle settings (legacy GLOBAL_SETTING keys read by Battle.battleAuto / battlePetAuto) and their validation.

/** bt<N> values: what bs<N> holds. */
export const AutoSlotKind = { NONE: 0, ITEM: 29, SKILL: 52 } as const;

/** Flat settings map: bs1..bs10, bt1..bt6, p2..p9 (all integers). Character and pet keys share one namespace. */
export type AutoBattleSettings = Partial<Record<AutoSettingKey, number>>;

export type AutoSettingKey =
  | 'bs1' | 'bs2' | 'bs3' | 'bs4' | 'bs5' | 'bs6' | 'bs7' | 'bs8' | 'bs9' | 'bs10'
  | 'bt1' | 'bt2' | 'bt3' | 'bt4' | 'bt5' | 'bt6'
  | 'p2' | 'p3' | 'p4' | 'p5' | 'p6' | 'p7' | 'p8' | 'p9';

export const AUTO_DEFAULTS: Required<AutoBattleSettings>; // p* = 10, bs*/bt* = 0

/** Pet keys: bs even + bs10, bt2/4/6, p6..p9. */
export function isPetAutoKey(key: AutoSettingKey): boolean;
export function isAutoSettingKey(key: string): key is AutoSettingKey;
/** Range check: p* 0..100, bt* in AutoSlotKind, bs* integer >= 0. */
export function validAutoValue(key: AutoSettingKey, value: number): boolean;
```

`PlayerData` gains `interfaceData?: AutoBattleSettings` (character keys merged with the active pet's keys, defaults filled).
The pet DTO used for the player's own pets (the type the pet list / active pet comes from) gains
`pi?: AutoBattleSettings` (that pet's bucket only) so the client can rebuild the pet half when the active pet changes.

Add unit tests `autoBattle.test.ts` for `isPetAutoKey` / `validAutoValue`.

## 3. Design

### 3.1 State

- `Character` schema (`server/src/modules/character/character.schema.ts`): `@Prop({ type: Object, default: {} }) interfaceData:
  Record<string, number>` — character keys only.
- Pet schema (`server/src/modules/pet/*.schema.ts`): `@Prop({ type: Object, default: {} }) battleSetting: Record<string, number>`
  — pet keys only. Existing documents read as `{}` → defaults; no migration script.

### 3.2 Static data

None new. Skill validation uses `GameDataService.skill(id)` + `SkillService.owns`; item template validation uses the existing item
template accessor in `GameDataService`.

### 3.3 Server

New module `server/src/modules/settings/` (`settings.module.ts`, `settings.rpc.ts`, `settings.service.ts`), registered in
`app.module.ts`:

- **Move `uif` here** from `pk/pk.rpc.ts` (only one `@Rpc('uif')` may exist). `uif(key, value, isPet)`:
  - `key === 'apvp'` → `PkService.setApvp` (unchanged behaviour; import `PkModule` / export `PkService`).
  - `isAutoSettingKey(key)`: value `Number(...)`, `validAutoValue` else `invalidArgs('value')`; `isPet` must match
    `isPetAutoKey(key)` (Flash always sends it correctly; mismatch → `invalidArgs('isPet')`). `bs*` with `bt* = 29` semantics:
    a non-zero `bs` set through `uif` must be an item template id (`invalidArgs('value')` otherwise). Pet keys require an active
    pet (`RpcException.forbidden('Chưa có pet xuất chiến')`), stored on that pet's `battleSetting`; character keys on
    `character.interfaceData`. `$set` of a single field.
  - other keys: ignored, reply `null` (as today).
- `skillSetBattle(skillId, level, slot, isPet)`: `slot = Number(args[2])` ∈ {1,3,5,7} (char) or {2,4,6,8} (pet), parity must
  match `isPet`. `skillId === 0` → `bt<slot>=0, bs<slot>=0`. Else template must exist and be a battle (non-passive) skill;
  character: `SkillService.owns`; pet: active pet's skill slots contain it. Writes `bt<slot>=52, bs<slot>=skillId`. Reply `null`.
- Login extra (`characters.addLoginExtra`): `interfaceData = { ...AUTO_DEFAULTS, ...character.interfaceData, ...activePet.battleSetting }`
  (pet keys of the defaults only overwritten by the pet bucket).
- Pet DTO mapping (pet module): add `pi: pet.battleSetting ?? {}`.
- No `quiet: true` on the new RPCs.

Combat (`server/src/modules/combat/`):

- `round.ts`: the 30-round cap applies to PvP only (legacy `Battle.HasRoundLimit`). PvE has no cap. Update `round.test.ts`.
- `battle-command.service.ts`:
  - Accept `BattleAction.AUTO` (-110) for character and pet: basic attack on a random alive enemy (Go `ClientActionAuto`).
  - Allow `ITEM` for a pet fighter: the item comes from the owner's bag (`session.characterId`), `room` is the pet's missing
    HP/MP, the heal lands on the pet (legacy pet item use). Add AUTO and ITEM to `PET_ACTIONS`.
  - Unit tests for the pure parts touched.

### 3.4 Client

- `client/src/game/battle/autoBattle.ts` (pure, no DOM/Pixi; < 300 lines) + `autoBattle.test.ts`:
  ```ts
  export interface AutoUnit { slot: number; side: 'player' | 'enemy'; kind: 'character' | 'pet' | 'creature';
    hp: number; hpMax: number; mp: number; mpMax: number; alive: boolean; front: boolean }
  export interface AutoInput { units: AutoUnit[]; self: number; skills: readonly LearnedSkill[];
    bag: readonly BagItem[]; settings: AutoBattleSettings; defend: boolean; rng: () => number }
  export interface AutoPick { cmd: BattleCommand; note?: string } // note = MP/HP-short toast
  export function autoCharacterCommand(input: AutoInput): AutoPick;
  export function autoPetCommand(input: AutoInput): AutoPick; // input.self = pet slot, skills = pet skills
  ```
  Implements the §1 chains. Items: `bs` = template id → first bag item with that `tid` → `{ tid: targetSlot, action: ITEM,
  id: bagItem.id, level: -1 }`; no item → skip the step. Item heals on another character (team heal) are skipped for the
  character (server heals own fighter only) — only self/pet targets. Skill commands send the learned skill's `sid`/`level`
  via `skillCmd`; a configured skill no longer learned → skip. "Front row" = the existing slot layout (`battle/slots.ts`).
  Tests: each chain step, thresholds, missing items, MP-short fallback, back-row targeting.
- `client/src/game/battle/autoState.ts` (small): `on` flag (module state, not persisted across reloads), `defendPlayer` /
  `defendPet` (localStorage `mc.autoDefend`, try/catch), change listeners for the HUD box.
- `BattleController.ts`: when `autoState.on` at `startRound()` (and the player or pet is alive) build commands with the
  functions above and `transmit([charCmd, petCmd?])` directly (fallen player: DEFENCE + pet auto). Battle menu shows the
  auto banner instead of the command column; "Kết thúc auto" turns auto off and opens the manual menu for the current round
  if nothing was sent yet. In-battle "Auto" button (`battleMenu.ts`): enabled, turns auto on and auto-picks this round.
  Keep `BattleController.ts` under ~300 lines: put the auto glue in `battle/autoRound.ts` if needed.
- `client/src/ui/battleMenu.ts`: enable `auto` button; add `showAutoBanner(onStop)` / `hideAutoBanner()` (title `Auto`,
  text `Auto hiện tại còn lại ∞ lượt.`, button `Kết thúc auto`), CSS in `ui/battle.css`.
- `client/src/ui/hud/userBar.ts`: the Auto box toggles `autoState.on`; label `Auto\nbật` when on, `Auto\ntắt` when off;
  tooltip `Nút tự động chiến đấu`.
- `client/src/ui/autoBattlePanel.ts` + `autoBattle.css` (new, DOM): panel "Tự động chiến đấu", two columns
  (Thao tác nhân vật / Thao tác pet). Each column: slot rows Phục hồi HP (+ slider), Phục hồi MP (+ slider), Pet hỗ trợ (+ slider)
  ×2, Kỹ năng tấn công with the hint text, checkbox Tự động phòng ngự. Clicking a slot opens a picker: learned battle skills
  (character: `initLearnedSkill`; pet: active pet's skills) and, for slots 1-6 and 9/10, potions in the bag (`HP_POTION` /
  `MP_POTION` from `game/potions.ts`; MP slots items only; attack slots 7/8 skills only), plus "Bỏ trống". Skill pick →
  `skillSetBattle(sid, level, String(slot), isPet)`; item pick → `uif('bt'+N, 29, isPet)` then `uif('bs'+N, tid, isPet)`
  (slot 9/10: only `bs`); clear item → `uif('bt'+N,0)`/`uif('bs'+N,0)`. Slider change (debounced 300 ms) → `uif('p'+N, v, isPet)`.
  Update the local settings on success; toast on error. Pet column disabled with a note when there is no active pet.
  Reuse `panelBehavior.ts` / existing panel styling (see `vipPanel.ts` or `titlePanel.ts` for the pattern) and `itemCell.ts`
  for icons.
- `client/src/ui/hud/miniMap.ts`: the "Auto" function button opens the panel.
- Settings source: `player.interfaceData` for character keys; the active pet's `pi` for pet keys (refresh when the active
  pet changes; `PetController` already tracks the active pet).

## 4. Non-goals

- Map auto-hunt / auto-path: does not exist in the Flash game.
- Character items on other characters (team heal by item): server ITEM heals the submitter's own fighter only; skills cover it.
- `us({...})` bulk save, hotbar lock (`ubl`), world-boss auto (`WBQUTOBATTLECANVA`), random PK (`autoBattleByRandom`),
  "Ủy thác" offline delegation (already covered by the offline module), buff 1203 still-encounter — separate features.
- The 150-round limit: legacy patched it away.
- Persisting the on/off auto flag across relogin (Flash does not).
