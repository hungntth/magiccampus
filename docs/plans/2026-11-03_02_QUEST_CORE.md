# Quest Core (newbie / main quests) — Implementation Plan

**Date**: 2026-11-03 · **Status**: Implemented (2026-11-03) — see "Implementation notes" at the end
**Goal**: a new character can do the newbie quest chain on Xuất Vân Thôn like in the Flash game: NPCs
show "!" / "?" markers, the "Đối thoại" dialog lists their quests, the quest panel shows the story text,
requirements and rewards with "Nhận" / "Xong" / "Bỏ", accepted quests appear in an on-screen tracker
whose "Tìm [NPC]" link walks to the turn-in NPC, and finishing grants exp (with level-up) and money.
Today `clickNpc` always sends an empty quest list and there is no quest state at all.

## 1. Confirmed mechanics

### Data (`data_tbl_quest*`, Mongo `_id` = `id`)
- `data_tbl_quest` (5530 rows) columns used: `id, name, info, start_text, complete_text, type, start_npc,
  finish_npc, min_level, max_level, gender (2 = any), req_class ("all" | "|1|" | pipe list), pre_quest_type,
  award_exp_re, money_num, money_type, color, at, is_rebirth, start_grant_item, start_grant_qty`.
- Quest types (client `GamePredef.as:348-359`): 1 NEWHAND, 2 MAIN, 3 CLASS, 4 WORLD, 5 BUSINESS,
  6 ACTIVITY/daily, 7 LOOP, 8 CHALLENGE, 9 CALLBOARD, 10 GROWUP, 11 GUILD, 12 LUCKY.
- `data_tbl_quest_require` (`qid, kind, type, item_id, num, q`): kind 1 collect item (type 29 item / 19
  equipment), kind 2 kill creature (type 12), kind 3 submit pet. No talk objective exists in data.
- `data_tbl_quest_pre` (`id, item_id, kind, num, qid, type`, 2016 rows): kind 1 = carry `num` of item
  `item_id`; kind 2 = quest `item_id` finished. **Not in Mongo today**: its seed
  (`D:\mcgame\supabase\seeds\data_tbl_quest_pre.sql`) is the only one of 99 written as
  `INSERT INTO data.data_tbl_quest_pre VALUES (...)` without a column list, which
  `server/tools/import-seeds.ts` `parseFile` regex does not match. Column order from
  `supabase/migrations/20260328184527_baseline_mcgame_schema.sql:1491-1498`: `id, item_id, kind, num, qid, type`.
- `data_tbl_quest_award` (`qid, kind, type, item_id, num, q`): item/equipment/pet rewards (not granted, §4).

### Can-accept rule (Go `service.go:91-195` = Flash `Player.canTakeQuest`)
Reject if: quest active or completed; level outside `[min_level, max_level]` (0 = unbounded); `gender != 2 &&
gender != char.gender`; `req_class` parses to a non-empty int list not containing `classId` (`"all"`, `"0"`, `""`
parse to empty = any); any kind-1 pre row (carry item); kind-2 pre rows: `pre_quest_type == 1` all finished,
`== 2` at least one finished, other values ignore kind-2 rows.

### NPC quest list and state (Go `npc_interaction.go:60-110`, `notify.go`)
- Entries for an NPC: every acceptable quest with `start_npc == npcId` → state 102; every active quest with
  `finish_npc == npcId` → 104 if all objectives met else 103 (overrides a 102 entry). NPC state = max entry
  state, `-1` when none. Same rule drives the head marker `onSetNpcState(npcId, state)`.
- State constants (`GamePredef.as:336-339`): 101 enough level, 102 can take, 103 taken, 104 can finish.
- Flash merges each list entry with its own static quest table (`DataManager.getChaQuestFullData`); a `data`
  key sent by the server replaces the static row. H5 has no static table, so the server must send it.

### RPCs (client call sites `QuestPanel.as`, server `lifecycle.go`, `manager.go`)
- `takeQuest(questId, npcId)` → reply `null` on success. Pushes in order: `onAddChaQuest(dto)`, accept-time
  grant items, `onSetNpcState` for {npcId, start_npc, finish_npc}. Client guard: 25 active quests max
  (`MAX_QUEST_NUM`, `QUESTPANEL_S[1]`). Client throttles take/finish/initQuestManager to 1 / 1100 ms.
- `finishQuest({i: questId, s: selectedAwardId | -1, n: npcId | -1})` (Go also accepts a bare id). Requires
  active + all objectives met. Reply `{flag:true, qid, qn}`; Flash reads `info` (not Go's `msg`) on failure.
  Client on success: `questLog += qid + '|'`, `qn = reply.qn`, remove from tracker, blue chat line
  "Hoàn thành nhiệm vụ: …", NPC says `complete_text` as a bubble. Server success pushes (Go order):
  `onAddMoney(charId, key, amount, newTotal)` per currency, `onUPP` exp/level (+ `onPlayerLevelUp`
  `{id, exp, lp, level, …}` on level-up), item/pet reward pushes, `onSetNpcState` for every NPC on the map.
- `cancelQuest(questId)` → push `onCancelQuest {flag, qid, qn, info?}`; type-1 quests cannot be cancelled
  (server `AbandonQuest` + client disables "Bỏ", `QuestPanel.as:932-939`).
- `initQuestManager()` → `{q: {"<qid>": dto}, completedIds, l}`; client reads only `q` (and `l`, loops).
- Login payload carries `questLog` (`"|id|id|"`, `"|"` when empty) and `qn` (int, active count).

### Active quest DTO (Go `helpers.go:40-60`, `service.go:219-368`; read by QuestCanvas/QuestGuide)
`qid, state (103|104), takeDate, data {id,name,info,type,startText,completeText,awardExp,moneyNum,moneyType,
startNpc,finishNpc,minLevel,color}, require[{kind,type,itemId,num,q,name?}], pos {map,x,y,name} (finish NPC),
fName (finish NPC name)`. A quest with no require rows is born 104 (immediately finishable). Do **not** send
`clsData` for non-class quests (QuestCanvas then prints "Số lần: n/10").

### Rewards (Go `service.go:1147-1437`, `character.go:545-614`, `player_level_exp.go`)
- exp = `award_exp_re`; money = `money_num` in `money_type`: 1 moneyBind, 2 money, 3 goldBind, 4 gold.
  Every newbie quest uses `money_type = 1`.
- Cumulative exp to reach level L = `LEVEL_EXP[L-1]`, `LEVEL_EXP = [1, 73, 358, 926, 1775, 3162, 5360, 8649,
  13232, 18510, 25771, 38644, 62425, 98030, 139609, 187700, 242854, 305634, 376620, 456403, 545587]`
  (levels 1..21). Auto level-up only while `level < 20` (`AutoLevelCap`); each level: `attrPoints += 5`,
  each of the 5 primary stats `+1`.

## 2. Shared contract (`packages/shared/src/protocol.ts`)

```ts
// --- Quests (takeQuest / finishQuest / cancelQuest / initQuestManager) ---

export const QuestState = { ENOUGH_LEVEL: 101, CAN_TAKE: 102, TAKEN: 103, CAN_FINISH: 104 } as const;
export const QuestType = { NEWHAND: 1, MAIN: 2, CLASS: 3, WORLD: 4, LOOP: 7, CALLBOARD: 9, GROWUP: 10 } as const;
export const MoneyType = { MONEY_BIND: 1, MONEY: 2, GOLD_BIND: 3, GOLD: 4 } as const;
export const MAX_QUEST_NUM = 25;

export interface QuestData {
  id: number;
  name: string;
  info: string;
  type: number;
  startText: string;
  completeText: string;
  awardExp: number;
  moneyNum: number;
  moneyType: number;
  startNpc: number;
  finishNpc: number;
  minLevel: number;
  color: number;
}

export interface QuestRequire {
  kind: number; // 1 item · 2 creature · 3 pet
  type: number; // template table: 29 item · 19 equipment · 12 creature
  itemId: number;
  num: number;
  q: number;
  name: string;
}

export interface QuestPos { map: number; x: number; y: number; name: string }

/** Quest as shown in the NPC dialog / quest panel (offered or active). */
export interface QuestView {
  qid: number;
  state: number; // QuestState
  data: QuestData;
  require: QuestRequire[];
  sName: string; // start NPC name
  fName: string; // finish NPC name
  pos: QuestPos | null; // finish NPC location
}

/** Active quest (onAddChaQuest, initQuestManager). */
export interface ChaQuest extends QuestView {
  takeDate: number; // epoch ms
}

export interface FinishQuestArg { i: number; s: number; n: number }
export interface FinishQuestReply { flag: boolean; qid?: number; qn?: number; info?: string }
export interface CancelQuestResult { flag: boolean; qid: number; qn: number; info?: string }
export interface InitQuestManagerReply { q: Record<string, ChaQuest> }

/** onUPP: partial player props after exp/money/level changes. */
export type PlayerUpdate = Partial<Pick<PlayerData, 'level' | 'exp' | 'money' | 'moneyBind' | 'gold' | 'attrPoints'>>;
export interface PlayerLevelUp { id: number; level: number; exp: number; lp: number }
// pushes: onAddChaQuest(ChaQuest) · onCancelQuest(CancelQuestResult) · onSetNpcState(npcId, state)
//         onAddMoney(charId, key: 'moneyBind'|'money'|'goldBind'|'gold', amount, newTotal)
//         onUPP(PlayerUpdate) · onPlayerLevelUp(PlayerLevelUp)
```

Changes to existing types:
- `NpcQuestEntry` → replaced by `QuestView` (`NpcFuncInit.npcQuest.list: Record<string, QuestView>`).
- `PlayerData` += `moneyBind: number; attrPoints: number; questLog: string; qn: number`.
- `SceneNpc` += `questState: number` (H5 extension: the Flash client sent one `setNpcState(npcId)` per created
  NPC; we fill it in `createNpcs` instead of N round trips; later changes come as `onSetNpcState`).

## 3. Design

### 3.1 State (new `server/src/modules/quest/`)
- `quest.schema.ts`:
  - `CharacterQuest` (collection `character_quests`): `characterId` (index), `questId`, `takeDate: Date`,
    `objectives: { kind, itemId, current, required }[]`; unique index `(characterId, questId)`. A row = active.
  - `QuestHistory` (collection `quest_history`): `characterId` (index), `questId`, `completedAt`; unique
    `(characterId, questId)` (only non-repeatable types are in scope).
- `Character` += `moneyBind: number` (default 0). Existing documents read the default; no script needed.
- `exp` stays **cumulative** (what the Flash client shows); level derived by the loop in §1.
- Restart story: everything is in Mongo; nothing in memory except static data.

### 3.2 Static data
- Fix `server/tools/import-seeds.ts`: when an `INSERT` has no column list, take columns from a
  `KNOWN_COLUMNS` map (`data_tbl_quest_pre: ['id','item_id','kind','num','qid','type']`); log an error
  (not silent) for a column-less insert of an unknown table. Re-run `pnpm import:seeds --only data_tbl_quest_pre`.
- `GameDataService` (new file `server/src/modules/gamedata/quest-data.ts` if `gamedata.service.ts` would pass
  ~300 lines): cache `data_tbl_quest` (5530 rows) and index `require`, `pre`, `award` by `qid`, quests by
  `start_npc`. Accessors: `getQuest(id)`, `questsByStartNpc(npcId)`, `questsByFinishNpc(npcId)`,
  `questRequire(qid)`, `questPre(qid)`. Item names for requires: look up `data_tbl_item_template` (type 29) or
  `data_tbl_equipt_template` (type 19) by id (query on demand, not cached); fall back to `"#<id>"`.

### 3.3 Server
- `quest.rules.ts` (pure, unit-tested): `parseReqClass`, `canAccept(char, tpl, active, done, preRows)`,
  `isSupported(tpl, requireRows)`, `applyExp(char, gained) → {level, exp, attrPoints, statGain, leveled}`,
  `LEVEL_EXP`, `questStateForNpc(...)`.
- **Supported quests (H5 slice)**: types {1, 2, 4, 10} only, and every require row must be satisfiable without
  inventory/combat: no rows, or a kind-1 row whose `item_id == start_grant_item` (accept-time grant, treated as
  met at accept and consumed on finish). Unsupported quests are never offered (not listed, no marker).
- `quest.service.ts`: `listForNpc(char, npcId) → {state, list}`, `npcState(char, npcId)`, `take`, `finish`,
  `cancel`, `active(charId) → ChaQuest[]`, `questLog(charId)`, `toView/toChaQuest` mappers.
- `quest.rpc.ts` (all `requireCharacter`, not quiet):
  - `takeQuest(questId, npcId)`: ints; quest exists, supported, `canAccept`; H5 hardening: `npcId == start_npc`
    and that NPC is on `session.mapId`; active count < 25. Errors → `RpcException.forbidden('<Vietnamese msg>')`.
    Insert row; push `onAddChaQuest`, then `onSetNpcState` for start/finish NPC if on the player's map; return `null`.
  - `finishQuest(arg)`: accept `{i,s,n}` or bare id; row exists, all objectives met; hardening: when
    `finish_npc > 0`, `n == finish_npc` and that NPC is on `session.mapId`. Delete row, insert history, add exp
    (level-up), credit money by type (1 → `moneyBind`, 2 → `money`, 3/4 → `gold` — no goldBind field; note it),
    save character. Pushes: `onAddMoney`, `onUPP`, `onPlayerLevelUp` if leveled, `onSetNpcState` for every NPC on
    the map. Reply `{flag:true, qid, qn}`. Failure → throw (gateway replies `ok:false`).
  - `cancelQuest(questId)`: type 1 → `{flag:false, info:'Không thể hủy nhiệm vụ này'}`; else delete row.
    Push `onCancelQuest(result)` and return it; push `onSetNpcState` for start/finish NPC.
  - `initQuestManager()` → `{q}`.
- `NpcService.buildFuncInit(npc, quests)` takes the `{state, list}` from `QuestService`; `NpcRpc` injects it.
- `SceneRpc.createNpcs` fills `questState` via `QuestService.npcState` (load the character's active rows +
  history once per call). `CharacterService.toPlayerData` gets `questLog`/`qn` from `QuestService` in
  `chooseCharactor` (keep the mapper pure: pass them in).
- Module wiring: `QuestModule` (imports `GameDataModule`, Mongoose features `CharacterQuest`, `QuestHistory`,
  `Character`), exports `QuestService`; `NpcModule`, `SceneModule`, `CharacterModule` import it.
  Avoid cycles: `QuestService` writes `Character` through its own model injection, not `CharacterService`.

### 3.4 Client
- `client/src/game/QuestController.ts` (new; keeps `GameScene` under the line cap): holds `ChaQuest` map,
  binds `onAddChaQuest`, `onCancelQuest`, `onSetNpcState`, `onUPP`, `onPlayerLevelUp`, `onAddMoney`; calls
  `initQuestManager` after scene load; exposes `take/finish/cancel` (1100 ms throttle each). Writes chat lines:
  "Nhận nhiệm vụ: <name>", "Hoàn thành nhiệm vụ: <name>", "Nhận được <n> Exp, <m> Tiền", level-up line.
- `Entity.setQuestState(state)`: Pixi text marker above the name — 102 yellow "!", 103 grey "?", 104 yellow
  "?", none otherwise (H5 placeholder; the Flash `STATE_ICON` art is in the undumped `ResManager`).
- `ui/npcDialog.ts`: below the text, one row per `list` entry sorted by state desc then id, label = name +
  state suffix; click → `QuestPanel.show(view, npc)`. Talk-only bubble rule unchanged (only when list empty).
- `ui/questPanel.ts` (new): NPC portrait + name (or "Hệ thống" when opened from the tracker), speech text =
  `data.startText`, `data.info`, "Yêu cầu nhiệm vụ:" lines (items "name (have/need)" with have = need for a
  granted item), "NPC nhận nhiệm vụ: <sName>", "NPC trả nhiệm vụ: <fName>", rewards "Exp <n>", "Tiền <m>".
  Buttons by state: 102 "Nhận"; 103 "Xong" disabled + "Bỏ"; 104 "Xong" + "Bỏ"; "Bỏ" disabled for type 1;
  "Xong" only when opened at the finish NPC. After a successful finish the NPC says `completeText`.
- `ui/questTracker.ts` (new): right-side panel "Nhiệm vụ", quests by `takeDate` desc, name prefixed
  "[Tân Thủ]" / "[Chính]" / "[Phụ]" (types 1/2/4); line " • Tìm <fName>" when state 104. Click name →
  quest panel (no NPC). Click "Tìm" → if `pos.map == current map` reuse `GameScene.onNpcClick(finishNpc)` (walks
  there and talks), else toast "<fName> ở bản đồ <map>".
- HUD: add `Exp` line (`exp` / next-level cumulative) and refresh on `onUPP`.

## 4. Non-goals

- Quests with item collection, kills, pet submission, quest battles (47+, 50, 166 …): no inventory or combat yet;
  they are simply not offered, so nothing half-works. The chain therefore stops after quest 46.
- Item / equipment / pet rewards (`data_tbl_quest_award`) are neither granted nor shown — no inventory yet.
  Quest 1 normally gives potions + gift bag, quest 3 a weapon, quest 4 a pet; revisit with the bag feature.
- Quest manager window (Q key, tabs "Đã nhận" / "Có thể nhận" / "Liên hoàn"): the tracker + panel cover the
  chain; the can-take tab needs the static quest table client-side.
- Loop, daily, class, callboard, guild quests; `takeBuildQuest`, `canQuest`, choose-one rewards (`at == 2`).
- Stat recalculation (HP/MP) on level-up and manual level-up beyond 20.
- Real quest marker art (ResManager `STATE_ICON` not in the dump) — text markers are a placeholder.

## Implementation notes (2026-11-03)

- `data_tbl_quest_pre` has **2017** rows (the seed has 2017 unique tuples), not 2016.
- NPC 430 (Sứ Giả Viên, finish of 161 and start/finish of 46) is on **map 3 (Vân Đài)**, not map 1. Quest 161 is turned in
  there (`/go 3`; the tracker "Tìm" shows a toast with the map name for other maps).
- Level progression over the real thresholds: Lv2 after quest 3 (101 exp), **Lv3 after quest 160** (360 exp; 288 < 358 after
  3191). Quest 161 requires Lv3, consistent with this.
- `LEVEL_EXP` is exported from `@mc/shared` (HUD shows exp / next-level threshold) and imported by `quest.rules.ts`.
- `canAccept` is backed by `acceptBlocker` (returns the Vietnamese reason used in the FORBIDDEN error).
- Accept-time grant items are not pushed (no inventory); the granted-item objective is simply stored as met.
- `GameScene` chat slash commands moved to `client/src/game/sceneCommands.ts` to keep GameScene near the line cap.
