# Dungeons & instances (M10) — Implementation Plan

**Date**: 2026-11-04 · **Status**: Approved (user, 2026-11-05) · Implemented (phases A-I, 2026-11-05; see the notes at the end)
**Goal**: port the instance layer of the legacy game:
- the phụ bản framework (opener quest + ticket, ruled entrance, per-day run, floors gated by bosses / steps / floor
  quest, gate guard, run timer + sweeper, leader-only quests with party credit, end chest, shared completion reward,
  once-per-day lock until 00:00, quick complete through the auto-task panel);
- the nine dungeons built on it (Mê Huyễn, Kho Báu, Kho Báu [Sự kiện], Lục Tiên, Liệt Diễm, Lang Huyệt, Quỷ Hút Máu,
  Thám Hiểm Di Tích, Thế Giới Số);
- star instance (Tinh Giới Thập Nhị Cung) + task sweep;
- boss towers: Kiếp Nạn Vô Ưu (nine boss), Hành Lang Vô Tận (corridor), Vùng Đất Rèn Luyện (trials);
- Mê Trận (maze), daily answer, quiz event, flop pass;
- training: Phòng Tu Luyện Ảo Ma + Ảo Ma Tháp (HMTXL), Khóa Học Đặc Huấn (TXKC), Vô Danh Động, Mật Đạo;
- world boss event, schedule-boss respawn, boss loot.

Today none of it exists in H5: NPCs with script menus show a placeholder, dungeon floor maps are reachable through
any gate, type-6 (daily) quests are unsupported, and the eight dungeon opener quests at NPC 200 cannot be taken.

Delivered in **ten phases (A, B–E, E2, F–I)**, each implemented, lint/test-verified and browser-checked before the
next. A is the foundation every other phase needs; E2 (boss mechanics engine) comes right after A because B, C, F and
I fight with the legacy boss kits; B–D are the dungeons; E–I are independent of each other after A + E2 (order is a
proposal). Implementation order: A → E2 → B → C → D → E → F → G → H → I.

- **Ruled entrance** (`handlers/npc/dungeon_mehuyen_entry.go`): without today's run the entrance NPC menu lists
  "Vào <name> - <difficulty>" (`dg_mh_<npc>_<level>`, `:80`). Intro `ruledIntro` / `ruledSoloIntro` (`:32-33`).
  Checks in order: a run closed today → `ruledClosedMsg` / `ruledAutoMsg`; daily lock → `ruledCooldownMsg`; clicker
  must lead a group when in one (`ruledNotLeaderMsg`); clicker + online non-AFK members ≥ minGroup (`ruledGroupMsg`);
  every member: level, carried ticket, no run today, no lock (`ruledMemberLevel/Ticket/Done/Cooling`, joined into
  `ruledMemberMsg`). Then every member spends one ticket (slot sync + loss notice), each gets the base run + rules run
  (difficulty, openedAt, leader; leader's run holds `party`), `ruledStartMsg`, leader is teleported to floor 1 (landX/Y
  or safe point) and members follow. With an open run the click falls to the generic menu: "Đến <Tầng N name>"
  (`dg_enter_<npc>_<floor>_<map>`) for every reached floor (`dungeon_portals.go:84-86`).
- **Floors** (`service.go:132-225`): floor i reachable when floors 0..i-1 are cleared; a floor is cleared when every
  `bosses` and `steps` NPC is in `run.beaten` and its `quest` was completed today (or party-credited). Floor NPC menu =
  quest entries + "Đến <Tầng N+1>" (`dg_next_<npc>`, `:118`); the player must stand on that floor
  (`dungeonWrongFloorMsg`); a refusal lists the pending parts (`dungeonPendingMsg` "Hãy hoàn thành tầng này trước: %s."
  with "đánh bại …", "kích hoạt …", "hoàn thành nhiệm vụ [..]", `:300-330`). No "Rời khỏi phụ bản" on floor NPCs
  (owner 2026-10-29, `:20`).
- **Gate guard** (`handlers/scene/gate_guard.go:16-31`, `service.go:273-294`): `sceneChange` into a floor map needs
  today's run and the floor reached; same or lower floor of the same dungeon always passes; refusal = `onMidNote` with
  the reason, player stays.
- **Fights** (`handlers/npc/dungeon_boss.go`, `service.go:227-271`): NPC on the clicker's map, run open, floor
  reached, NPC not yet beaten. Line-up from `data_tbl_npc_creature` of the NPC (level = row level, else creature
  `use_lv`, else dungeon level; boss row in the centre). Win (no flee): every player-side character with a run gets
  the NPC in `beaten` (dead members included); "Đã đánh bại %s." / "Đã đánh bại %s. Tầng này đã hoàn thành, có thể đến
  tầng tiếp theo." (`:33-36`); normal exp, creature loot and kill credit. No line-up → "%s chưa có dữ liệu đội hình
  chiến đấu.". Already beaten → "%s đã bị đánh bại trong lượt phụ bản hôm nay.".
- **Leader-only quests + party credit** (`mehuyen_rules_party.go`): floor quests are hidden from members (take
  blocked); the leader's turn-in credits every party member's rules run (`credited[qid]`), which counts as "completed
  today" for their floor gates and chest. Dead leaders still get kill credit when the party won.
- **Sweeper** (`handlers/npc/dungeon_mehuyen_sweep.go`, every 15 s, skips characters in battle): first sighting on a

## 3. Decisions for H5

1. **Single process**: no lines. `lockChannel`, `wb_line_id` and "đang ở kênh khác" checks are dropped; the sweeper
   reads the scene manager. Recorded per feature.
2. **Day keys**: every day / week / month key uses `@mc/shared` `dayKey` (UTC+7). Midnight locks use
   `nextDayStartMs(now)` from the same helper (add it with tests if missing).
3. **State**: one Mongoose document per character and feature with a `rev` CAS: `character_dungeons`,
   `character_star_instance`, `character_towers` (nine boss + corridor + trials sub-objects), `character_maze`,
   `character_answer`, `character_flop`, `character_training` (hmtxl + hmt_tower + txkc), `character_autotask`. The
   sweeper's "tracked" set is derived from persisted runs + the scene manager each tick (no in-memory set to lose on
   restart). Event state (quiz, world boss) stays in memory (as Go) with persisted per-character outcomes.
4. **Seed overlays**: the importer writes each file to a collection named after the file
   (`data_tbl_plan_khobau`, …). A new `gamedata/overlays.ts` lists the overlay collections **explicitly** per base
   table (prefix matching would mix `data_tbl_npc_creature` into `data_tbl_npc`) and `GameDataService.rowsWithOverlays
   (base)` unions them (overlay ids are disjoint, 9xxxxxx). Base tables: `data_tbl_npc_creature`, `data_tbl_plan`,
   `data_tbl_creature_loot`, `data_tbl_quest_require`, `data_tbl_creature_skill`, `data_tbl_item_award`,
   `data_tbl_buff`, `data_tbl_boss_loot`, `data_tbl_npc` (`data_tbl_npc_daily_answer`).
5. **Importer fixes** (`server/tools/import-seeds.ts`): accept `INSERT INTO "data"."t" AS alias (…)` (today
   `data_tbl_buff_mehuyen.sql` is silently skipped) and unqualified `INSERT INTO t`. UPDATE-only seeds
   (`data_tbl_quest_quyhutmau.sql`, `data_tbl_quest_thegioiso.sql`, `data_tbl_npc_khobau_event.sql`) are **not**
   parsed: their values become TS constants in `gamedata/overlays.ts` (`QUEST_REWARD_OVERRIDES`, `NPC_AT_OVERRIDES`)
   applied at load. Re-run `pnpm import:seeds` (drop + insert per collection, idempotent) and diff counts.
6. **Type-6 quests**: `QuestType.DAILY = 6` joins `SUPPORTED_QUEST_TYPES`; `quest_history` becomes an upsert
   (`completedAt` refreshed) so "done today" = `completedAt ≥ today start` for type 6 (others: ever). `rt`/`rn` turn-in
   cost is ported (refusal "Không đủ tiền để hoàn thành nhiệm vụ!", charged before items are consumed). `lm` stays
   unused (Go ignores it too). A `QuestGate` hook lets the dungeon module block takes (abandon lock, leader-only).
7. **NPC script menus**: port `onList(npcId, title, info, options)` + `npcScript(func)` and a server registry of click
   hooks and script hooks (`NpcHookRegistry`, ordered; first claimer wins). Func ids are kept verbatim from Go so logs
   map back. Clicks on type 10/19/20 NPCs ask the hooks first, then the quest battle (existing).
8. **Instance NPCs**: `createNpcs` gains per-viewer providers (`InstanceNpcProvider.npcsFor(session, mapId)`); live
   changes push `onNpcOn(InstanceNpc)` / `onNpcOff(id)`. `InstanceNpc` carries `nid` (template id for art / name) so
   instance ids (1623001, 9014101, 900001…) are free. H5 draws from the payload, so no client data table is needed.
9. **Battle context + hooks**: `Battle.ctx?: BattleContext {source, bossNid?, floor?, ...}` and a
   `BattleEndHooks` registry (called once after settle with `{battle, result, members}`); `battlePlayEnd` can return a
   hook-provided reply (star report). Round cap becomes per battle: default 30, `ctx.roundCap` (boss towers / world
   boss / dungeon bosses 150). Encounter exp / loot can be suppressed per source (world boss).
10. **Boss mechanics are ported, not deferred** (user decision 2026-11-04): NPC skill execution + skill pools at a
    raised roll, summons, round revives and death rules, the Hydra split, openers, immunities, death marks, the elite
    kit, the Chu Ma clone, the Mehdi kit, corridor summons / openers / floor kits, VDRL death rules / summons and Ngày
    Diệt Vong are added to the H5 engine in **Phase E2** (after A, before B's boss fights) as pure modules under
    `combat/mechanics/`, following the Go round pipeline and play-list shapes. Fights ship with the full legacy kit;
    the only engine piece not ported is the dashboard-only `boss_strength_override` table (no data).
11. **Gift bags**: H5 cannot open `data_tbl_item_award` bags yet (M11). Rewards that are bags (corridor first kill,
    world boss 3584-3588, quiz 4875, explorer bags) are **unpacked at grant time** by a shared
    `ItemAwardService.unpack(templateId, rng)` (rows `type` 29 item / 30 currency / 35 game currency, `rate`,

12. **Systems H5 lacks**: medals (`updateMedalInBag`: Ấn Chương rows / medal 460 / 56 / 67 / 78 / 89, Mê Trận 122),
    explorer medal (Điểm Mạo Hiểm), Công Trạng (rebirth exp), mail. Medal rolls are skipped and logged; the pool entry
    "Ấn Chương Hiền Giả" is re-rolled. World boss / quiz mail fallbacks become a persisted "owed" list granted on the
    next claim or login (`onSystemSay` "Phần thưởng đã được cất giữ, hãy dọn túi rồi nhận lại.").
13. **Currencies**: add `petguardin` 201, `couragePoint` 214, `txkc2508p` 69 to `CURRENCY_IDS`; Chiến tích
    (`expBattle`, world boss) uses the existing ranking honor field if present, else a currency `honor`; record which.
14. **Gold**: every gold price is real `gold` (Go "Vàng only"); top-up stays not ready (gold from `gmGrant`).
15. **Simplified world**: no flying in H5 — Liệt Diễm floor 4 air Phù Thủy and Vô Danh Động airHunt are placed / played
    on the ground (implementer picks walkable points with the client hit mask and records them). Type-24 pick-ups are
    instant (no hand-pick bar). Kind-6 "use" objectives are credited by the server (`QuestProgressService.credit
    (cid, qid, requireId, n)`) and shown by the H5 tracker (Flash could not).
16. **Leader-only quests** kept as Go (members are credited for floors and chest, not quest rewards).
17. **GM**: no admin dashboard; GM-gated RPCs `gmWorldBoss(action, minutes?)`, `gmQuiz(action)` and chat commands
    `/wb start|stop`, `/quiz start|stop`, `/dg reset <key>` (requireGm).
18. **Maze copy maps**: one room per character: scene room key `maze:<cid>` on template maps 2007-2009; position
    writes are dropped inside (relog lands at the return point), as Go.
19. **Content numbers** (line-ups, pins, rewards, rates marked "our choice" in Go) are ported as-is from the legacy
    tables; tuning knobs live in one `*-config.ts` per feature.

## Implementation notes (phase E2.-1 damage alignment, 2026-11-05)

Done; lint clean, tests shared 158 / swf 4 / server 677; battle bot (watchbot, map 2, attack mode) fought two encounters with
no server errors. Ported from Go `domain/combat/damage.go` (current), `dodge_chance.go`, `evasion_rule.go`, `level_gap.go`,
`turn_builder.go` into `combat/damage.ts` (formula) and the new `combat/strike.ts` (strike sequences; moved out of
`round.ts`, which drops to 173 lines):
- **Formula order** (`resolveHit`): melee-only proportional dodge `0.5·d/(d + 9·hit)` (cap 0.5; ranged / magic skills never
  dodge) → base `atk × mult + base`, × `1 + 0.02·level` for NPC attackers only → XPN roll `(defy − resiDefy) / 100` (cap 1) →
  Miễn Giảm ≥ 100 % without XPN = resisted ("Kháng cự") → defence `atk / (atk + def / 4)` (level constant only for a zero
  attack stat; XPN ignores defence) → enhance → Miễn Giảm (cap 100 %, skipped on XPN) → Giảm ST Cuối `praDef / praMagDef` of
  the **defender** (cap 75 %, also on XPN; V1 had wrongly used the attacker's praDef as penetration) → crit `(Bạo − Kháng bạo)
  / 100` uncapped below 100 %, × `(200 | 250 Xạ Thủ + bonus) / 100` → floor 1 → element (Go table) → 10-level gap (× 0.2,
  player side vs enemy NPC, not on XPN) → variance → round → **position modifier on the main hit** (Go
  `getPositionModifier` over the slot grid: Flash slots 10-14 and 0-4 are both "back" rows, so melee main hits are × 0.7,
  ranged × 0.9, as live Go) → defend halves. The M2 "position 1.0" deviation is dropped (decision 15).
- **Crit damage**: `criticalDmg` now holds Go's value (characters / creatures / pets 200 + bonus; the multiplier is
  `(class base + bonus) / 100`), so plain crits are × 2.0 (× 2.5 Xạ Thủ) instead of V1's × 1.5.
- **Combo / counter** (`strike.ts`): basic attack chains up to 10 extra × 0.6 hits (`comboExtraHits`, combo ≥ 100 always 10),
  rolled even after a dodged / resisted first hit, moving to a random living enemy (TurnTo + Run) when the target dies;
  skills get one extra hit at `combo / 100` (melee and in-place casts); counter cap 100 %, needs a landed or resisted main hit
  of a melee basic attack, struck in place (TurnTo, Attack, hurt, TurnBack, no Run / Back), chains its own combo, and can be
  countered back alternately up to 5 times.
- **Miễn Tử** (`deathImmune`): a lethal hit leaves 1 HP once per battle at `(rebornRate − breakReborn) / 100`; tSObj
  `reborn: hp`. **Miss texts**: tSObj `status` "Né tránh" / "Kháng cự" (Go `miss_display.go`), `miss: true` kept.
- **Heals**: NPC-only level bonus, crit at the caster's Bạo × `(150 + bonus) / 100`.
- **Stats wired**: `CombatStats.defy / rebornRate / breakReborn` (optional) from `finalDefy / finalRebornRate /
  finalBreakReborn`; creature `element` from `data_tbl_creature.element` (0-6, else 0); characters stay element 0 (Vô: the
  gear-dominant element is not computed in battle yet), pets keep theirs. Skill specs carry `ranged` (category ≠ melee).

  Multiplier` adapter is not used for player skills (flagged in memory).
