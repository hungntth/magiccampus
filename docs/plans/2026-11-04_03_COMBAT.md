# Combat (M2): solo PvE battles, rewards, revive, kill/collect quests, skills — Implementation Plan

**Date**: 2026-11-04 · **Status**: Approved (2026-11-04, including the H5 decisions marked in §1)
**Goal**: walking on a monster map rolls random encounters. A turn-based battle stage opens over the map: the player against
1–2 creatures. The player attacks, defends, drinks a potion, flees or casts a skill, and the server resolves the round and plays it back
with animations and damage popups. Winning gives exp, money (Bạc khóa), quest-item loot and kill-quest credit. Losing leaves the player at
0 HP with a free revive dialog. Quest-battle NPCs (type 20, e.g. NPC 475 "Kê Vương" for quest 50) start a battle on click. The
newbie/main chain can then continue past quests 47–50 (collect and kill). Today there is no combat at all.

Delivered in **three phases**, each implemented, lint/test-verified and browser-checked before the next one starts:
- **A — Battle core**: encounters, stage, commands, damage, end, exp/money, death and revive.
- **B — Quests and loot**: loot, collect/kill objectives, quest-battle NPCs.
- **C — Skills**: learned skills, the skill command, MP cost.

Research base (the implementer reads both):

  participant (§3.3), turn flow (§3.4), damage (§3.5, Go-invented), rewards/loot/kill credit (§3.6), skills (§3.7), revive (§3.8), state (§4),
  tables (§5), push sequences (§6), port notes (§7), id pairings for map 3 / quests 47–50 (§5).

## 1. Confirmed mechanics

Marked *(H5)* where we deliberately differ from, or fill a gap in, the legacy behaviour.

### 1.1 Start
- `cbom(x, y)` is fire-and-forget. The client sends it after moving ≥ 100 px since the last check point, throttled to 1 per 1000 ms,
  and never on safe maps (`safeFlag > 0`). It resets the check point only at battle start.
  - Server: map `basic_battle_rate` 0 → never; otherwise clamp to [0.30, 0.75] (seeds hold 0 and 50, so a flat 30 %).
  - 4 s cooldown per character; safe maps are skipped.
  - *(H5)*: no encounter while in a battle or at HP 0.
- Enemy roll: 1–2 enemies (capped by the number of distinct normal rows). Each slot rolls `rand()*100` against the
  `data_tbl_map_creature` `[start_rate, end_rate)` ranges, falling back to a random row. Rows with `boss_flag != 0` are excluded.
  Level cap as in server research §3.3.
- Slots: enemies `0, 2, 1, 4, 3` (in fill order), the solo player at `10`.
- Quest-battle NPC: `clickNpc` on an NPC of type 10, 19 or 20 starts a battle (server research §3.2).
  - `sub_type` is a quest-id list; one enemy per incomplete kill objective of an active quest in that list.
  - Enemy level `max(1, min_level/2)`, exp `level*10`.
  - If no listed quest is active, the normal NPC dialog is used.
  - Example: NPC 475 on map 3, quest 50 → creature 157.
- Start push order: `onSetCharState({cid, state: 5})` to self, the same broadcast to the map, then `onBattleStart(BattleStart)`.

### 1.2 Round
- `battleUpdateCmd([cmd])`, with `cmd = {tid, action, id, level}`:
  - attack: `tid` = target slot;
  - defend `-20`, flee `-30`, timeout `-40`: `tid -1`;
  - item `-60`: `id` = bag item row id;
  - skill `-50`: `id` = skill id (phase C).
- One call resolves the whole round:
  - each living enemy gets a basic attack on a random living player-side target;
  - actors act by speed, descending, random ties;
  - a dead or missing target makes the attack a miss with `tid -1` (no retarget);
  - a victory check runs after each actor; at round 30 the enemy wins.
- Defend: damage taken is `trunc(dmg/2)` and the hurt uses behaviour 6. Timeout `-40` = defend animation **without** the reduction.
- Escape always succeeds: the battle ends with `result 2`, no rewards, HP/MP kept.
- Item: a consumable with a heal amount (`inventory/potion.ts` table, food `i1/i2`). It is consumed first; the heal is capped at the effective max and
  carried in `tSObj.rHp` / `rMp`.
- Timer: the client counts 25 s and then sends `-40`. Server deadline 30 s (5 s checker); on expiry the missing command becomes `-40`.
  *(H5)*: the deadline is re-armed after every round, including timeout rounds (legacy forgot to).
- Push per round: `onBattlePlayList(groups)`. When the round ends the battle, push `onUPP({currentHp, currentMp})` **before** the playlist.
  The RPC reply is `null`. Legacy `onCmdReady` is only for grouped rounds and is not sent.

### 1.3 Damage (Go V1 formula, server research §3.5; Go-invented, adopted as our rule)
- Use the pseudocode in server research §3.5 with:
  - basic attack: `base 10, mult 1.0`, physical, melee;
  - no elements (all 0);
  - combo and counter from `rates.finalCombo` / `finalCounter` (0 without gear).
- *(H5)*: the position modifier is **1.0**. Go's row mapping makes every melee hit x0.7 by accident (research §3.5 item 40).
- Overkill: `tSObj.hHp` carries the unclamped `preHp - dmg`; the participant HP is clamped to 0.
- Creature participant stats: server research §3.3 (`att_*`/`apt_*`/`grow_base`/`life`/level scaling). Test vectors: creature 56 Lv3 → hp 51,
  atk 3, def 30, speed 103; creature 157 Lv2 → hp 374, atk 64, def 320.
- Player participant: the M1 effective stats from `CharacterStatsService` (current HP/MP, max, attack, defence, hit, dodge, crit, speed, rates).

### 1.4 Playback (client research §6, server research §6)
- `groups: BattleStep[][]`. Steps in a group run together; the next group starts when all finish.
  Step keys: `sid, tid` (slots), `bid`, `sSObj`, `tSObj`, `delay`.
- Melee attack sequence: TurnTo 10110 → Move 1 → [Attack 3 + Hurt 5 (or 6 when defending)] in one group → Die 10120 (creature) / 4 (player) if lethal
  → Back 10080 → TurnBack 10100. Delays per server research §6.
- Defend: `bid 0` self. Flee: `bid 10130`. Item use: `bid 7` with `tSObj.rHp`.
- `hHp` / `rHp` are the **new** HP; the client shows the popup `old - new` (red, size 32; crit size 50 plus a shake).
- The last step of the ending round is `{end: true, result}` (1 win, 0 loss, 2 fled) plus the H5 extension `report`.
  *(H5)*: the Flash star-report window (`type` truthy) is not used, so `type` is omitted.
- Hit or cast effects: **none**. The only Go default (`2080130010008` → `EFF_PLAYER_010008`) is not in the asset cache.

### 1.5 End
- Rewards are settled when the battle ends, inside the final `battleUpdateCmd` (Go).
  - Exp per dead creature: `level*10` (or the `exp` column of its map row when > 0), times the level-diff modifier (research §3.6 item 45).
  - Money: `sum(level*5)` → `moneyBind`.
  - Level-up through the existing `applyExp` (auto below 20).
  - HP/MP are persisted at the end. *(H5)*: they are persisted at settle time, not at `battlePlayEnd`, so a disconnect cannot lose them.
- `battlePlayEnd()`: the client sends it after playing the end marker. It returns the character to the map. Push order (server research §6):
  1. quest pushes (`onAddChaQuest` / `onSetNpcState`), phase B;
  2. `onUPP` stats;
  3. `onPlayerLevelUp` if leveled;
  4. `onAddItem` + `onAddCharactorSlot` for loot (phase B);
  5. `onAddMoney`;
  6. `onSetCharState({cid, state: 1})`, also broadcast to the map.
  - *(H5)*: if the session closes before `battlePlayEnd`, the same settlement (incl. kill credit) is finalized on disconnect.
- Defeat: no penalty, HP stays 0. After the end the client calls `reliveSwitch()` when `currentHp <= 0`.
  - *(H5)*: `reliveSwitch` returns `2`, the free dialog with a 20 s countdown.
  - `freeRelive(1)`: revive in place with full HP/MP.
  - `freeRelive(2)` / `toSafe()`: move to the map's `safe_x/safe_y` with half HP/MP.
  - *(H5)*: these only act when HP is 0, and the result is pushed as `onUPP` (plus a position update for `toSafe`).
  - The item-721 / gold variants are not used.

### 1.6 Quests and loot (phase B)
- Loot: `data_tbl_creature_loot` rows by `cid`.
  - Rows with `qid > 0` drop only while that quest is active; the rate is x5 (cap 50000) for an item still needed by an active collect objective.
  - Roll `rand(50000)+1 <= rate`; quantity `qtyMin..qtyMax`; bound when `b == 1`.
  - Item types 508/509 (quest items) go into the normal bag. *(H5)*: there is no quest bag yet.
  - Money/exp rows (types 30/31/35) are not ported.
  - The H5 bag must have space; otherwise the drop is skipped with `onRedMsg('Túi đồ đã đầy')`.
- Kill objectives (`quest_require` `kind 2, type 12, item_id = creature id`):
  - On a win, each dead creature adds +1 to the first incomplete matching objective of each active quest.
  - Push `onAddChaQuest` with `questKill: [{creatureId, num}]`, where `num` is the **remaining** count.
  - When the quest becomes finishable, also push `onSetNpcState`.
- Collect objectives (`kind 1`): counted from the bag; there is no push on drop (the client recounts).
  - `finishQuest` checks the bag. The implementer verifies in Go `application/quest` whether collected items are **consumed** on finish
    and follows Go (two sources: Go code plus the quest text/requirement); record the finding in the plan notes.
- `isSupported` (quest.rules.ts) widens to accept kill and collect objectives, so quests 47–50 become takeable.
- Tracker text: `(required - num)/required`, with " (Hoàn thành)" when `num <= 0`.

### 1.7 Skills (phase C)
- Class start skills (`data_tbl_class.start_skill`, e.g. class 1 `1010|1086`) are learned at character creation. Existing characters get them through an idempotent script.
- `initLearnedSkill()` returns the skill list. The battle skill menu lists learned **active** skills; type 11 (passive) is refused as a command.
- Skill command `-50`:
  - The server checks ownership and the MP cost (`useMp`: < 1 = fraction of final MP, ≥ 1 absolute). Not enough MP → it falls back to a basic attack.
    The client pre-checks with "MP không đủ, không thể sử dụng kỹ năng [..]".
  - Damage uses the Go adapter: `base 10, mult 1.0`, physical when `type == 1` (melee approach), otherwise magic and cast in place (`bid 7`).
  - `sSObj.skill` = name (banner), `sSObj.uMp` = new MP.
  - Target count 1 in M2.

## 3. Design

### 3.1 State
- Battles live **in memory** in `BattleManager` (a server singleton): `battleId → Battle` and `characterId → battleId`.
  - On restart or disconnect, the battle is finalized as fled (or settled, if it already ended), with HP/MP persisted.
  - There are no Mongo battle documents.
- `Session` gets `battleId: string | null`. While it is set:
  - `udcp`/`udcr` moves are ignored;
  - `sceneChange`/`gmGoMap`, `cbom`, `clickNpc`, shop buy/sell and bag/equip ops are refused with `RpcException.forbidden('Đang chiến đấu')`;
  - `useItem` outside a battle command is refused.
  Implement with an `inBattle` check helper used by those RPCs (or a `forbidInBattle` decorator option if it fits `rpc.decorator.ts` cleanly).
- Phase B: quest progress needs kill counters. Add `kills: Record<string, number>` (creatureId → count) to the active-quest subdocument in
  the quest schema, default `{}`; no migration.
- Phase C: `character_skills` collection `{characterId, skillId, level, position}` (unique char + skill), or an array field on the character.
  Pick the collection (matches legacy). Seed via `server/tools/learn-start-skills.ts` (idempotent) and at `CharacterService.create`.

### 3.2 Static data (`GameDataService`)
- Cache at startup:
  - `data_tbl_map_creature` (by map);
  - `data_tbl_creature` (the columns needed for stats, name, res_code, level, boss_flag, exp);
  - `data_tbl_creature_loot` (by cid, phase B);
  - `data_tbl_skill` (phase C).
- Map row: `basic_battle_rate`, `safe_flag`, `safe_x/safe_y` (already loaded?). The implementer verifies the column names against Mongo
  (`docker exec mcgame-mongo mongosh mcgame --quiet --eval ...`).

### 3.3 Server
- New module `server/src/modules/combat/`, files < 300 lines each:
  - `battle.types.ts` (internal participant/battle);
  - pure `creature-stats.ts` (+test), `damage.ts` (+test, with an injectable RNG), `round.ts` (+test: ordering, miss on dead target, defend,
    escape, victory, round cap; builds the `BattleStep` groups), `encounter.ts` (+test: rate clamp, row roll), `rewards.ts` (+test: exp modifier, money);
  - `battle.manager.ts` (in-memory registry, deadlines, disconnect hook);
  - `combat.service.ts` (start / round / settle / end);
  - `combat.rpc.ts` (`cbom`, `battleUpdateCmd`, `battlePlayEnd`);
  - `revive.rpc.ts` (`reliveSwitch`, `freeRelive`, `toSafe`);
  - `combat.module.ts`.
- Phase B: `loot.ts` (+test), quest kill hooks in `quest.service.ts` (`onCreatureKilled(charId, creatureId)` returning the pushes),
  `quest.rules.ts` `isSupported` + collect/kill completion checks (+tests), `clickNpc` bridge in the npc module calling `CombatService.startQuestBattle`.
- Phase C: `modules/skill/` (`skill.schema.ts`, `skill.service.ts`, `skill.rpc.ts` with `initLearnedSkill`); `round.ts` skill branch.
- Reuse: `CharacterStatsService` for player stats and the HP/MP write-back, `InventoryService` / `UseItemService` helpers for the battle potion
  (consume first, then heal), `CharacterService.addMoney`, quest `applyExp`, `SceneManager.broadcast` for `onSetCharState`.
- Disconnect hook: the gateway's session-close path must call `BattleManager.onSessionClosed(session)`; check how `scene.manager.ts` handles closes and follow it.
- Deadlines: one `setInterval` every 5 s in `BattleManager` (`OnModuleDestroy` clears it).

### 3.4 Client
- `game/BattleController.ts`: net and state machine.
  - It handles `onSetCharState`, `onBattleStart`, `onBattlePlayList`.
  - It sends `cbom` from the movement code (every ≥ 100 px since the last check point, 1 s throttle, not on safe maps, not in battle or at 0 HP).
  - It hides the HUD, chat stays, and the map stops reacting to clicks during battle.
- `game/battle/BattleStage.ts`: Pixi container over the map.
  - Background: a snapshot of the map view with a colour tint (normal `(1, 1.1, 1)`, boss `(1.1, 1, 1)`) and a dark overlay at alpha 0.6 (the `UI_LOADING_BACK` art is not needed).
  - Slot coordinates from client research §4.2 (900×570 stage).
  - `BattleUnit` (sprite + 50×4 HP bar + name). Enemies face dir 1, players dir 5.
  - Sheet action indices: 0 stand, 1 run, 3 attack, 4 dead, 5 hurt, 6 defence, 7 magic. Note that `docs/assets-pipeline.md:32` swaps 4/5; fix that doc line.
  - Creature sheets come from the existing `resPath` / `SheetAnim` loader; characters use the same sheet as their map entity.
- `game/battle/playback.ts`: runs `BattlePlayList` group by group.
  - Each step has a behaviour end: a move tween at 58 px/frame at 24 fps, stopping 60 px short; attack and hurt play their action once; die fades over 1 s.
  - Damage popups (`ui` text in Pixi, red 32 px, crit 50 px + shake, "Né" for a miss).
  - A safety timeout per step (2 s) so playback never stalls.
  - At the `end` step it shows the report toast (exp, money, items), calls `battlePlayEnd`, and restores the map/HUD. If HP is 0 it then calls `reliveSwitch` and opens the revive dialog.
- `ui/battleMenu.ts` + `battle.css`:
  - Buttons Tấn công, Phòng ngự, Kỹ năng (C), Vật phẩm (potions in the bag), Bỏ chạy.
  - Attack and skill enter target selection (click an enemy unit).
  - 25 s countdown that turns red at 9 s and sends `-40` at 0.
  - The menu is hidden during playback. Next-round sends wait ≥ 4 s after the previous playback started (client research §5).
- `ui/reviveDialog.ts`: free dialog with a 20 s countdown. "Hồi sinh" → `freeRelive(1)`, "Về thành" → `freeRelive(2)`. On timeout → `freeRelive(2)`. Strings from client research §9.
- Phase B: quest tracker shows kill progress from `questKill`; `onAddChaQuest` updates it.
- Phase C: the skill submenu lists `initLearnedSkill` active skills with MP cost and the client MP pre-check.

## 4. Non-goals

- Pets, catch, group/party battles, PvP, watch/replay, arena, world-boss: later milestones (roadmap tiers 2 and 4).
- Hit/cast/bullet effects: the assets are missing (`EFF_PLAYER_010008` not in the cache); popups carry the feedback.
- Buffs and status effects in battle (poison, dizzy …), per-battle buff decrement, elements: no M2 source applies them.
- Auto-battle, `setBp` front row, sneak attacks (`sneakFlag` always 0), `clickBoss` / `hitNpc` visible monsters: no M2 map content needs them.
  Random encounters and quest NPCs cover the chain.
- Paid revive variants (item 721 "Hình Nhân", gold, world-boss): Go never charged either.
- Skill learning/upgrade at trainers (`skillLearnByClient`), skill bar (`skillSetBattle`/`skillSetUserBar`), multi-target/AoE skills, skill
  cooldowns, real skill damage tables (the seed has no damage columns).
- Money/exp loot rows (types 30/31/35), quest bag (types 508/509 go to the normal bag), boss loot.
- Battle persistence across server restarts.

## 5. Verification

1. Unit tests:
   - creature stats against the two vectors (§1.3);
   - damage with a seeded RNG (defend halves, min 1, crit, dodge clamp);
   - round ordering by speed, miss `tid -1` on a dead target, escape result 2, round cap;
   - encounter rate clamp and row roll;
   - exp modifier and money;
   - (B) loot roll and x5 rule, kill credit "remaining" count, `isSupported` for quests 47–50;
   - (C) MP cost fraction vs absolute, passive refused.
2. `pnpm --filter @mc/shared build`, `pnpm -r lint`, `pnpm -r test`. Baseline: shared 4, swf 4, server 95.
3. Manual smoke test (browser; server log shows every RPC):
   - **A**:
     1. `/go 3`, then walk around. Within a few hundred px a battle starts.
     2. Attack until the enemies die (popups, death fade). The end toast shows exp/money and the HUD returns.
     3. Defend, flee and potion each work.
     4. Set HP low via mongosh and lose. The revive dialog appears; "Hồi sinh" restores full HP and "Về thành" moves to the safe point with half HP.
     5. While in battle, map clicks do nothing.
   - **B**:
     1. With a character on the quest chain at 47, take 47.
     2. Kill creature 4 on map 3 until item 516 drops; the tracker counts it; finish the quest.
     3. Repeat for 48/49. Quest 50: click NPC 475 to fight Kê Vương; the tracker shows 1/1 (Hoàn thành), then finish.
   - **C**: the battle Kỹ năng menu lists the class start skill; casting it spends MP (bar drops, banner shows the name); with too little MP it shows the MP warning.
4. Docs: new `docs/memory/combat.md` (+ index line); update `quest.md` (kill/collect) and `character-stats.md` (skills or a new `skills.md`).

Go finding (`D:\mcgame\internal\application\quest\service.go`, `CompleteQuest` :653, `syncCollectObjectives` :728, `consumeCollectObjectiveItems` :858):
- **Collected items ARE consumed on finish.** `CompleteQuest` first re-syncs every collect objective from the bag (`current = min(count of carried items by template /

Deviations / decisions:
- **Category mapping follows the Go adapter (research 3.7), not the plan's one-liner**: type 1 = physical melee (approach sequence); types 2 and 8 = physical but cast in place
  (bid 7); types 3 and 4 = magic cast in place; types 5 and 9 = heal; type 11 = passive. The plan text said "otherwise magic"; ranged physical skills (hunter 2114) would
  otherwise use magic attack. The mapping lives in `@mc/shared` `skill.ts` (`skillCategory`) so client and server agree.
- **Heal skills are implemented** (not in the plan's damage-only text): healer 1903 would otherwise hit an enemy. The caster is the target, heal = Go `executeHealSkill`
  (`trunc((base + magAtk * mult) * (1 + level * 0.01) * [0.9, 1.1])`), shown as `tSObj.rHp`. The client sends heal skills at once with `tid` = own slot (no enemy click).
- **Buff / debuff types (6, 7, 10) are refused** server-side ("Kỹ năng chưa được hỗ trợ") and hidden from the menu: statuses are an M2 non-goal. No start skill uses them.
- **MP cost**: `skillMpCost` (shared): `useMp` in (0, 1) = `ceil(fraction * max MP)` (at least 1; Go floored it to 0), >= 1 absolute. The client pre-check uses the same helper on the
  battle unit's MP (kept fresh by `sSObj.uMp`) and shows `MP không đủ, không thể sử dụng kỹ năng [name] ` as a red toast without sending anything.
- Server not-enough-MP: the command becomes a basic attack on `tid` (or the first living enemy when `tid` is not an enemy, e.g. a heal skill cast without MP); nothing is spent.
  Ownership is checked first (`forbidden`), then passive / unsupported refusal (`forbidden`), then MP. Skill level scaling (`level` arg) is not applied (all learned levels are 1).
- Round: MP is spent before the hit; the cast's first playlist step carries `sSObj = { skill: name, uMp }`. Magic / ranged casts skip combo and counter. MP is persisted by the
  existing settle write (`currentMp` from the fighter), so a flee / disconnect keeps the spent MP.
- Learning: `CharacterService.create` calls `SkillService.learnStartSkills` (idempotent `$setOnInsert` upsert on the unique `characterId + skillId` index). `CharacterModule` imports
  `SkillModule`. `GameDataService.skill(id)` serves `SkillTemplate` rows built by `gamedata/skill-data.ts`.

  "skill rows created: 0".
- Client: skills are fetched with `initLearnedSkill` at every `onBattleStart` (no `GameScene` change; it was not touched). Picking an enemy skill arms `pendingSkill` and the next
  enemy click sends `{ tid, action: -50, id: sid, level }`; "Tấn công" clears it.
