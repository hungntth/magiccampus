- Pet stat registry: `modules/pet/pet-stat-provider.ts` + `PetStatRegistry` (PetModule export). Feature modules import PetModule and `register()` in `onModuleInit` (talent in `pet-boost/pet-talent.provider.ts`). Pass a context to `PetBonusService.extrasOf(cid,row,ctx)`; combat uses `'battle'`.
- PetModule must NOT import ProgressionModule/PetBoostModule: Progression -> Title -> CharacterModule -> PetModule is a real cycle ("TitleModule imports[4] undefined", server does not boot). Read `character_features` by model (`CharacterFeature`) in pet code instead.
- Item ids in training RPCs are bag item INSTANCE ids; look at the template (`material().tpl.color/prop_type/propl_num`), never compare ids to template ranges.
- Sheet aptitude: `sheetAptitudes()` in `pet-view.ts`; `aptRefined` 0 = unrefined (mongoose zero defaults), Vu Hoa derived from `envoInfo` via `featherAptitudes`.
- Smoke recipe: scratchpad `m12a_fix.js` (pets/items 960001+ for hudtest, bag slots 120+), `m12a_bot.mjs <scenario>`, `m12a_clean.js`; restore gold/moneyBind and `$unset` `currencies.npPnt` + `activePetObject` (do not unset both a path and its parent in one update).
- Scripted replace via `node -e` failed on CRLF `pet.module.ts` although `grep -c $'\r'` said 0; use the Edit tool or normalise `\r\n` first.
- Slice 2: handbook / contract providers live in PetModule (`pet-feature-providers.ts`, registered in `onModuleInit`; they only read the Character doc). Nest ctor params must be injectables: a `rng: () => number = Math.random` ctor param breaks DI, use a class field.

Edits with apostrophes in heredocs: write the .mjs with the Write tool, then run it.
