# PixiJS Client

Conventions for `client/` (Vite 6, PixiJS 8, plain DOM for UI, TypeScript strict, `Bundler` module
resolution — no extensions on relative imports). `CLAUDE.md` is authoritative.

## Structure

- `main.ts` — app bootstrap and the connect → login → char select → world loop (reconnects on close).
- `net/client.ts` — `GameClient`: `call<T>(method, ...args): Promise<T>` (rejects with
  `RpcClientError{code, method}`), `on(callback, handler)` returning an unsubscribe function,
  `onClose(listener)`.
- `game/GameScene.ts` — world container, map, entity maps (`players`, `npcs`), camera, click-to-move,
  server sync; `bindCallbacks()` registers push handlers into `this.offs`, `destroy()` releases them.
- `game/Entity.ts` — player/NPC display object; uses a converted sheet when the `resCode` has one,
  else icon + marker. `game/SheetAnim.ts` — sheet loader/player (`loadSheet`, `Behavior`, directions
  0..7 counter-clockwise from south). `game/MapLayer.ts` — single-image/tiled maps.
  `game/HitMask.ts` — walkability bitfield.
- `ui/` — DOM overlays in `#ui` (`screens.ts`: login/char select/`toast`; `chat.ts`: `ChatBox`, `Hud`).
- `assets.ts` — `iconUrl(code)`, `resUrl(code)`, `mapTileUrl(...)`: resource code → `/res/<md5>`.
- `@mc/shared` resolves to `packages/shared/src` through the Vite alias (no rebuild needed for the
  client); Vite proxies `/ws` and `/res` to the server on :4000.

## Patterns

- **Types**: every RPC result and push payload is typed from `@mc/shared`
  (`client.call<SceneLoginResponse>('sceneLogin')`, `client.on('onCR', (d) => this.onRemoteMove(d as MoveUpdate))`).
  If a type is missing, add it to `packages/shared/src/protocol.ts` — never declare a local copy.
- **Push handlers** live with the object whose lifetime they share; push the unsubscribe into that
  object's `offs` and call them in `destroy()`. Handlers must tolerate arriving before assets load.
- **Errors**: `.catch((e) => toast((e as Error).message, true))` on fire-and-forget calls; never leave
  a rejected promise unhandled. `RpcClientError.code` distinguishes `INVALID_ARGS`, `NOT_FOUND`, …
- **UI**: DOM elements created in TypeScript and appended to `#ui` (no framework). Keep each panel a
  class or function in `client/src/ui/<panel>.ts` with a `destroy()`/remove path; styles in
  `style.css`. Player-visible text is Vietnamese, matching the original game's wording from
  `Language.as` when porting.
- **Pixi**: add display objects to the scene's containers (`world`, `entityLayer` with
  `sortableChildren` and `zIndex` = y for depth), never directly to `app.stage` from feature code.
  Load textures with `Assets.load`; destroy with `{ children: true }` when removing. Per-frame logic
  goes through the scene `tick(dt)`, not extra tickers.
- **Assets**: character/NPC/effect/item art comes from `client/public/sheets/<family>/<NAME>.{png,json}`
  (generated by `tools/swf`, format in `docs/assets-pipeline.md`), resolved from a `resCode` via
  `decodeResCode` (see `sheetNameFromResCode`). Icons/map tiles stream from `/res/<md5>` via
  `assets.ts`. If a sheet is missing, regenerate with the `swf-asset-pipeline` skill — never hand-edit
  generated files.
- **Coordinates**: server positions are map pixels (`posX`, `posY`), directions 0..7 as in
  `SheetAnim`; movement routes are `number[][]`.

## Workflow

1. Read `CLAUDE.md`, `docs/memory/<feature>.md`, and the scene/UI files you'll touch.
2. For ported features, get the original UI behavior/strings from `flash-client-researcher` (or the
   plan's §1) instead of guessing.
3. Shared types first; then net calls and push handlers; then rendering/UI.
4. `pnpm --filter @mc/client lint` (and `pnpm -r lint` if shared changed).
5. Run it: `pnpm dev:server` + `pnpm dev:client`, open http://localhost:5173 and exercise the change
   (use the `run` skill for browser-driven checks or screenshots). Watch the browser console and the
   server log.
6. Update `docs/memory/<feature>.md`.

## Completion checks

- Lint clean; no local duplicates of shared types.
- Push handlers unsubscribed on destroy; no unhandled promise rejections.
- Verified in the running client (or clearly reported as not run).
